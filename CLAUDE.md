### Тестирование производительности

| Метод | Описание |
|-------|----------|
| `run_full_benchmark` | Запуск полного теста (13 операций) |
| `run_quick_benchmark` | Быстрый тест (запуск + RAM/CPU) |
| `_spreadsheet_worker` | Основной рабочий поток стресс-теста |
| `_bench_launch` | Замер времени запуска Р7-Офис |
| `_bench_text_input` | Тест ввода текста (10000 символов) |
| `_bench_memory` | Замер потребления RAM |
| `_bench_cpu` | Замер загрузки CPU |
| `_bench_close` | Закрытие Р7-Офис |
| `_get_r7_processes(log_cb=None)` | Поиск процессов Р7-Офис по psutil (editors_helper, desktopeditors, r7, р7, x2t — конвертер документов); кэширует PID; список обновляется перед каждым отдельным замером (не один раз за тест), чтобы ловить x2t, запущенный в середине теста; `log_cb` по умолчанию `self.add_test_log` |
| `_sample_r7_resources(procs)` | Снимает RAM (МБ), CPU (сырое и нормализованное делением на `psutil.cpu_count()`), число потоков и аптайм по списку процессов; общий метод для `_spreadsheet_worker` и `_batch_run_single_version` |
| `_log_resources(sample, log_cb=None)` | Форматированный вывод замера в лог с цветовым индикатором нагрузки CPU: 🟢 <50% (норм.), 🟡 50–79.9%, 🔴 ≥80% |

## Правила работы с кодом

### 1. Импорты
- Стандартные библиотеки: `os`, `sys`, `time`, `threading`, `json`, `csv`, `hashlib`, `subprocess`, `winreg`, `shutil`, `re`, `tempfile`, `pathlib`, `datetime`, `tkinter`, `webbrowser`
- Сторонние: `pyautogui`, `psutil`, `pyperclip`, `openpyxl`, `win32gui`, `win32con`

### 2. Координаты и разрешение экрана
- НЕ использовать жёсткие координаты (например `pyautogui.click(x=800, y=400)`)
- Использовать `pyautogui.click(button='right')` без координат, или клик по центру найденного окна
- Навигацию по листам делать через горячие клавиши (`Ctrl+PageUp`, `Ctrl+PageDown`)

### 3. Замеры времени
- Не включать `time.sleep()` внутрь измеряемых функций
- Паузы выносить в `post_action_delay()` после `measure()`
- Для ожидания загрузки данных использовать динамическое ожидание через `Ctrl+End`

### 4. Обработка ошибок
- Все вызовы `win32gui.SetForegroundWindow` оборачивать в try/except
- Таймауты для `subprocess` обрабатывать с `proc.kill()`
- Проверять права администратора перед запуском тестов

### 5. Логирование
- Использовать `add_test_log()` для вывода сообщений
- Логировать начало и конец каждой операции
- При ошибках писать в лог с префиксом "❌"

### 6. UI
- Не блокировать главный поток длительными операциями — использовать `threading`
- Обновлять UI через `root.after(0, callback)`
- Прогресс-бары и статус-бар должны обновляться

## Запуск программы

```bash
# Установка зависимостей
pip install -r requirements.txt

# Запуск (обязательно от администратора)
python r7_Testovarka.py
```

## Отладка
- Лог выводится в текстовое поле на вкладке "Производительность"
- При ошибках программа не должна падать — показывать messagebox
- Для диагностики проблем с окнами использовать `find_r7_window()`

## Примечания
- Р7-Офис в диспетчере задач называется `editors_helper.exe`
- Процесс может называться также `DesktopEditors.exe` или `Р7-Офис`
- Файлы с расширением `.xlsx.xlsx` — ошибка двойного расширения, нужно исправлять в коде
- Координаты для кликов определяются динамически через центр активного окна
