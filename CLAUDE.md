### Закрытие Р7-Офис

| Метод | Описание |
|-------|----------|
| `_close_r7_gracefully(hwnd, log_cb, timeout)` | Закрывает конкретное окно Р7 через `WM_CLOSE` (не слепой `Alt+F4`, который уходил тому окну, что имело фокус в этот момент). Диалог «Сохранить изменения?» гасится в два независимых пути (см. ниже). Если окно не исчезло за `timeout` секунд — принудительно завершает процесс через `_terminate_r7_processes`. Используется во всех трёх сценариях закрытия (одиночный тест, Batch, тест своего файла) |
| `_cdp_dismiss_save_dialog()` | Адаптер над `R7WebDriverConnector.dismiss_save_dialog()`: жмёт «Не сохранять» в DOM-модалке. Гасит исключения, возвращает текст нажатой кнопки либо `None` |
| `_cancel_blocking_dialogs(owner_pid, log_cb, max_rounds)` | Отменяет модальные окна ОС, из-за которых Р7 не реагирует на `WM_CLOSE` (прежде всего «Сохранить как», оставшийся от неудавшегося экспорта в PDF). Вызывается **до** `WM_CLOSE`. Заголовки — в `BLOCKING_DIALOG_TITLES`, кнопки — в `CANCEL_BUTTONS` |
| `_terminate_r7_processes(log_cb)` | `terminate()` → `kill()` для процессов, не откликнувшихся за 3 сек. Крайняя мера — раньше её не было, и зависший диалог сохранения оставлял процесс висеть до ручного вмешательства |

#### Сначала снять блокирующий модальный диалог

Пока на экране висит модальное окно ОС — прежде всего «Сохранить как» от теста «Сохранение в PDF», если экспорт не довели до конца, — `WM_CLOSE` главному окну **не делает ничего**: весь timeout уходит впустую и заканчивается принудительным завершением. Поэтому `_close_r7_gracefully` начинает с `_cancel_blocking_dialogs`.

Здесь безопасно жать именно «Отмена»: отмена экспорта в PDF ничего не портит (файл временный). А вот у диалога «Сохранить изменения?» отмена означала бы «не закрывать Р7», поэтому его заголовок в `BLOCKING_DIALOG_TITLES` **не входит** — маска составная (`сохранить как`, а не голое `сохранить`), и на это есть тест.

Такой диалог — настоящее окно ОС, его заголовок через `win32gui` читается (в отличие от кнопок внутри него), поэтому искать его по заголовку можно.

#### Два пути гашения диалога «Сохранить изменения?»

Порядок в цикле ожидания внутри `_close_r7_gracefully`:

1. **Отдельное окно ОС** — ищется по owner PID среди top-level окон того же процесса (не по тексту заголовка) и закрывается через `_click_priority_button`. Работает только если сборка Р7 рисует диалог классическими Win32-виджетами.
2. **HTML-модалка внутри окна редактора** — у неё нет ни своего окна ОС, ни дочерних HWND (та же причина, что и у кнопки «Жирный»: Qt+CEF рисует всё сам). Кнопка «Не сохранять» жмётся по тексту прямо в DOM через CDP — `_cdp_dismiss_save_dialog`. Опрашивается не чаще `CLOSE_CDP_RETRY_SEC` (1 с), чтобы не спамить websocket и лог при шаге цикла 0.2 с. `connect()` идемпотентен и вызывается один раз перед циклом: коннектор создаётся при запуске Р7, но `connect()` до этого зовётся лениво только из `_wait_for_bold_button_cdp`, и если триггер готовности ни разу не сработал — соединения бы не было.
3. Не помогло ничего — принудительное завершение процесса.

Форс-килл здесь — **штатный** запасной путь, а не авария: для бенчмарка потерять несохранённые правки тестового файла безопаснее, чем вслепую нажать Enter. Кнопка по умолчанию в этой модалке — «Сохранить», и слепое подтверждение перезаписало бы эталонный тестовый файл; Escape же отменяет само закрытие. Поэтому — только точное попадание по «Не сохранять» либо честный kill.

Диагностика, без которой этот баг не воспроизводился: раньше в `_click_priority_button` из этого места передавался глушитель `lambda _m: None`, и дамп дочерних окон молча выбрасывался. Теперь он пишется (один раз за закрытие). Отдельно логируются заголовок и класс окна-кандидата — `_click_priority_button` печатает дамп только когда дочерние окна ЕСТЬ, а у Qt-диалога их нет вовсе, и именно этот случай раньше не оставлял в логе ничего.

### Замер отдельной операции

Формула: `elapsed = момент_простоя_Р7 − старт − self._paced_total`. Пороги — константы класса `OP_*`.

| Метод | Описание |
|-------|----------|
| `_pace(seconds)` | Преднамеренная пауза внутри операции; копится в `_paced_total` и вычитается из замера |
| `_confirm_modal_enter(pace)` | Часть подтверждения модалки «Вставить ячейки», которая обязана быть ВНУТРИ замера: одна пауза `OP_DIALOG_PACE` + один Enter. Ставит флаг `_pending_modal_confirm`. Общий код для `copy_paste_context` и `paste_pkm` |
| `_flush_pending_modal_confirm(log_cb)` | Досылает оставшиеся страховочные Enter'ы уже ВНЕ замера. Вызывается в обоих воркерах сразу после `_wait_operation_done` |
| `_wait_for_window_title(substrings, timeout)` | Ждёт окно с заголовком. Это реакция Р7, поэтому НЕ вычитается; вызывающий код сам добавляет к `_paced_total` безрезультатное ожидание |
| `_wait_operation_done(hwnd, log_cb, start_grace)` | Ждёт, пока Р7 освободится. Занят = окно не прокачивает очередь ИЛИ CPU процессов Р7 выше `OP_IDLE_CPU_PCT` ИЛИ жив x2t. Возвращает `(момент, статус)`, где момент — НАЧАЛО простоя, поэтому окно подтверждения не попадает в замер |

Статусы: `ok`, `below_floor` (Р7 не стал занят за `start_grace` — операция быстрее порога измерения, в отчёте помечается «<порога»), `timeout`.

Предохранитель на операцию — `OP_MAX_WAIT_SEC` (180 с), но тест-функция может попросить свой, более короткий, через `self._op_max_wait` (сбрасывается перед каждым замером рядом с `_op_start_grace`). Так сделан Ctrl+A: выделив весь лист, Р7 считает агрегаты статусной строки по всем ячейкам и на большом файле держит CPU занятым десятками секунд — с общими 180 с это выглядело как зависание инструмента. `OP_SELECT_ALL_MAX_SEC = 20`: не успел — операция честно помечается `timeout`, прогон идёт дальше.

Экспорт в PDF выставляет `self._op_start_grace = OP_PDF_GRACE_SEC` перед отправкой клавиш: x2t стартует не сразу после Enter, и при обычном окне старта операция помечалась бы `below_floor`. Ожидание старта в замер не попадает — оно стоит только времени прогона.

Правки в тест-функциях обязательно зеркалить в `_batch_run_single_version`: места и величины пауз должны совпадать, иначе Batch и вкладка «Производительность» дадут несравнимые цифры. Это касается и CDP-пути (см. «Операции тестов через CDP»): попытка через api и клавиатурный запасной путь должны быть одинаковыми в обоих воркерах.

#### Модалка «Вставить ячейки»

Диалог сдвига ячеек (вниз/вправо) в тестах «Вставка N ячеек (ПКМ)» — HTML внутри CEF, отдельного окна ОС у него нет, поэтому дождаться его появления через `_wait_for_window_title` невозможно: остаётся слепой Enter. PR #4 добавил второй Enter, но оставил его на `OP_MENU_PACE` (0.12 с) — на нагруженном документе модалка не успевала отрисоваться, Enter уходил в сетку, а диалог оставался висеть и ломал все последующие операции прогона. Отсюда «баг вернулся»: гонка, а не отсутствие фикса.

Поэтому подтверждение разнесено на две части с `OP_DIALOG_PACE = 0.6`:

* `_confirm_modal_enter()` — **внутри замера**: одна пауза + один Enter. Пауза идёт через `_pace()` и вычитается, и это корректно ровно потому, что Р7 в этот момент простаивает, показывая модалку.
* `_flush_pending_modal_confirm()` — **вне замера**, сразу после `_wait_operation_done` в обоих воркерах: досылает оставшиеся `OP_DIALOG_ATTEMPTS − 1` Enter'ов обычным `time.sleep`.

Почему нельзя все три Enter'а держать внутри замера (так было в первой версии этой правки, поймано на ревью): `_pace()` вычитается из результата, а сразу после подтверждающего Enter Р7 **начинает работать**. Сон и вычитание в этот момент отнимают у результата время, которое Р7 реально считал: при трёх паузах из замера уходило 1.8 с, и «Вставка 1 ячейки» (заметно короче секунды) стабильно давала 0 / `below_floor`. Вычитать можно только паузы, в течение которых Р7 простаивает.

Повтор безопасен и делает последовательность самоисправляющейся: лишний Enter в сетке лишь сдвигает активную ячейку на строку вниз, а следующий тест всё равно начинается с `Ctrl+Home`, — какой бы из Enter'ов ни совпал с появлением модалки, она закроется.

### Определение готовности документа

Замер «Открытие файла» заканчивается, когда `_wait_until_r7_ready` подтвердит готовность. Пороги — константы класса `READY_*`, общие для одиночного теста, теста своего файла и Batch-режима (прежние две копии ожидания разъехались: `STABLE_SECS` 10 против 8).

| Метод | Описание |
|-------|----------|
| `_window_responsive(hwnd, timeout_ms)` | `SendMessageTimeout(WM_NULL)` — возвращается ровно тогда, когда окно прокачало очередь сообщений. Прямое измерение занятости UI-потока |
| `_wait_until_r7_ready(hwnd, timeout, log_cb)` | Ждёт совпадения двух признаков: окно отзывчиво И процессы Р7 простаивают `READY_IDLE_SAMPLES` замеров подряд при отсутствии живого `x2t`. `hwnd` принимает дескриптор либо функцию его поиска (тогда устаревший дескриптор перерешивается). Возвращает `False` при таймауте и при исчезновении всех процессов Р7 |

Почему нужны оба признака: Р7 грузит данные в фоновом потоке и остаётся отзывчивым, поэтому одна отзывчивость срабатывает слишком рано; один простой CPU может совпасть с зависшим окном. Отдельно нужен контроль `x2t` — конвертер стартует уже после появления окна редактора, и пауза перед его запуском иначе читается как готовность.

Что делать, если открытие больших файлов стало определяться преждевременно: поднимать `READY_IDLE_SAMPLES`, не трогая `READY_POLL_SEC`.

#### Доп. триггер: кнопка «Жирный»

Внутри `_wait_until_r7_ready`, в момент первого совпадения признаков «окно отзывчиво» + «CPU простаивает», метод пробует объявить готовность раньше обычного накопления `READY_IDLE_SAMPLES`, проверив доступность кнопки «Жирный» на панели инструментов. Не чаще раза за вызов, по порядку:

1. **CDP** (`_wait_for_bold_button_cdp`, `r7_webdriver_connector.py`) — через Chrome DevTools Protocol. Панель инструментов Р7 — HTML внутри CEF-рендера, а не нативные Win32-виджеты, поэтому это единственный способ, который реально видит кнопку `<button id="id-toolbar-btn-bold">` в DOM (внутри iframe `apps/spreadsheeteditor/main/`). Работает, только если Р7 в этом запуске стартован с `--ascdesktop-support-debug-info` (`_prepare_webdriver_launch`, вызывается перед каждым из 3 мест `subprocess.Popen`, запускающих Р7: `_spreadsheet_worker`, `_batch_run_single_version`, `_worker_run_test`). CDP-порт **фиксирован на 8080** (не настраивается через `--remote-debugging-port` — этот флаг не подтверждён как работающий, см. docstring модуля); если 8080 занят, пробуются 8081/8082 с этим флагом на пробу, если и они заняты — CDP для этого запуска отключается, тест идёт по обычному пути. Порт 8080 и локатор кнопки подтверждены на живом Р7-Офис (2026-08-24).
2. **win32gui** (`_wait_for_bold_button`, `_find_bold_button_hwnd`) — `EnumChildWindows` по классу `Button`/`ToolbarButton`. Эмпирически подтверждён неработающим на установленной сборке (2026.2.2.x, Qt+CEF) — оставлен как fallback на случай сборки с классическими Win32-виджетами на панели.
3. Если оба не сработали — обычная логика CPU + `WM_NULL`, как без этого триггера вообще.

`r7_webdriver_connector.py` — опциональный модуль (импортируется в `try/except ImportError`, флаг `WEBDRIVER_OK`, как `WIN32_OK`/`PYAUTOGUI_OK`). Без пакетов `requests`+`websocket-client` (или `selenium` сверху — необязателен, добавляет попытку атача через `webdriver.Chrome(debuggerAddress=...)` перед голым CDP по websocket) программа работает как раньше. `self._webdriver_connector`/`self._current_webdriver_port` — состояние на один запуск Р7, закрывается в `finally` тех же трёх функций (`_close_webdriver_connector`), рядом с остановкой монитора диалога обновления.

Публичный интерфейс коннектора: `connect()` (идемпотентен), `connected`, `bold_button_state()`, `dismiss_save_dialog()` (жмёт «Не сохранять» в DOM-модалке выхода), `dump_visible_ui()` (диагностика) и общий `evaluate(js)`, на котором построены остальные. DOM-знание (селекторы, рекурсия по iframe) живёт в этом модуле, а не в `r7_Testovarka.py`.

При обрыве websocket (`ConnectionAbortedError`, `WebSocketConnectionClosedException` — Р7 рвёт CDP, когда начинает закрываться) `_mark_disconnected` разрывает бэкенд: `connected` становится `False`, `evaluate()` сразу отдаёт `None`, сообщение в лог пишется один раз. Без этого закрытие, опрашивающее CDP раз в секунду, наполняло лог одинаковыми ошибками и продолжало ждать ответа вместо перехода на win32gui-путь.

##### Диагностика слепой навигации по меню

`_cdp_dump_ui(label, log_cb, once_key, charge_pace)` пишет в лог фактические подписи видимых кнопок и пунктов меню, как их видит DOM. Нужна потому, что контекстное меню обходится стрелками вслепую (`down` N раз + Enter): стоит меню обзавестись лишним пунктом — счётчик уезжает и нажимается не то, а по `win32gui` этих подписей не видно в принципе. Печатает один раз на ключ за прогон.

`charge_pace=True` относит длительность дампа в `_paced_total`. Ставить только там, где Р7 гарантированно простаивает (раскрытое меню, открытая модалка) — иначе вычтем время, которое Р7 работал.

##### Если `WEBDRIVER_OK=False` при живом модуле — смотреть на интерпретатор, а не на код

Уже случалось: при ручной проверке `python -c "import r7_webdriver_connector"` флаг `True`, а в логах приложения `False`. Причина была не в коде — `requests`/`websocket-client` стояли в системном Python, но не в `E:\R7Manager\.venv`, которым приложение реально запускается. В `requirements.txt` они закомментированы как опциональные, поэтому `pip install -r requirements.txt` их не ставит. Проверять так:

```bash
.venv/Scripts/python.exe -c "import requests, websocket; print('ok')"
.venv/Scripts/python.exe -m pip install requests websocket-client
```

Диагностика на этот случай встроена: `except ImportError as e` печатает причину, плюс безусловная строка `🔍 WEBDRIVER_OK после импорта: ... (файл: ..., cwd: ...)` — путь к файлу в ней сразу показывает, тот ли модуль подхватился.

Важно: эти `print` с эмодзи требуют, чтобы `sys.stdout` умел UTF-8. Консоль Windows по умолчанию cp1251/cp866, и на ней такой `print` падает `UnicodeEncodeError` ещё до создания UI, — поэтому сразу после импортов стоит `sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")` в `try/except` (учитывая, что под `pythonw.exe` оба потока могут быть `None`).

### Операции тестов через CDP

7 из 13 операций выполняются не клавишами, а вызовом внутреннего api редактора
через CDP. Клавиши остаются запасным путём: если CDP в этом запуске недоступен
(нет `requests`/`websocket-client`, Р7 стартован без `--ascdesktop-support-debug-info`,
порт занят, api не нашёлся в DOM) — тест идёт ровно так, как шёл раньше.

| Тест | Через CDP | Клавишами (fallback) |
|------|-----------|----------------------|
| Выделение всех ячеек | `asc_EditSelectAll()` | Ctrl+A |
| Копирование всех ячеек | `asc_Copy()` | Ctrl+C |
| Вставка большого массива | `asc_addWorksheet()` + `asc_Paste()` | Shift+F11, Ctrl+V |
| Добавление нового листа | `asc_addWorksheet()` | Shift+F11 |
| Добавление столбца (оба варианта) | `asc_showWorksheet(-1)` + `asc_findCell("B1")` + `asc_insertCells(InsertColumns)` | Ctrl+PageUp, →, Ctrl+Shift+= / Alt+I, C |
| Вставка N ячеек (горячие клавиши) | `asc_findCell("A1:<N>1")` + `asc_Copy()` + `asc_findCell("<offset+1>1")` + `asc_Paste()` | Ctrl+Home, Shift+→, Ctrl+C, →, Ctrl+V |
| Вставка N ячеек (ПКМ) | то же, но последним шагом `asc_insertCells(InsertCellsAndShiftDown)` | ПКМ → меню → модалка сдвига |

`ВПР`, `Удаление столбца (Del)` и `Сохранение в PDF` на CDP не переводились и
идут клавишами.

#### Почему api редактора, а не `document.execCommand` / `navigator.clipboard`

Сетка Р7 — это `<canvas>`: строк, столбцов и ячеек в разметке нет вовсе,
редактор рисует их сам. Поэтому `execCommand('selectAll')` выделил бы текст
HTML-страницы, а не ячейки листа; команд `insertColumn`/`insertSheet` в
спецификации `execCommand` нет в принципе; `execCommand('paste')` из скрипта
отключён во всех современных движках, а `navigator.clipboard.writeText`
требует user activation, которой у вызова из CDP нет.

Рабочий рычаг — экземпляр `Asc.spreadsheet_api`, тот самый объект, чьи
`asc_*`-методы дёргают кнопки тулбара и пункты меню. Имена сверены с
установленной сборкой: `Editors/editors/sdkjs/cell/sdk-all-min.js`, там же
`Asc.c_oAscInsertOptions = {InsertCellsAndShiftRight:1, InsertCellsAndShiftDown:2,
InsertColumns:3, InsertRows:4}`. `asc_Copy`/`asc_Paste` на десктопной сборке
уходят в `asc_desktop_copypaste` — то есть в системный буфер обмена, туда же,
куда и настоящий хоткей.

Сам экземпляр создаётся приложением редактора внутри iframe
(`this.api = new Asc.spreadsheet_api(...)` в `web-apps/.../app.js`), под
глобальным именем, на которое полагаться нельзя. Поэтому `findApi` в
`r7_webdriver_connector.py` спускается по фреймам и проверяет кандидатов
(`Asc.editor`, `editor`, `SSE.getController('Main').api`) по наличию
`asc_EditSelectAll`.

| Метод | Описание |
|-------|----------|
| `_cdp_ensure_connected(log_cb)` | Подключает коннектор запуска, если он ещё не подключён. `connect()` зовётся лениво из `_wait_for_bold_button_cdp`, и при быстро открывшемся файле триггер до CDP-ветки не доходит — тогда соединения нет и все операции молча ушли бы на клавиши. Вызывается в обоих воркерах до `_capture_cdp_ui_baseline` |
| `_cdp_log_api_info(log_cb)` | Один раз за запуск пишет в лог, найден ли api и каких методов у него нет. Без этой строки «CDP-операция не сработала» неотличимо от «api не найден вовсе» |
| `_cdp_step(caption, fn, log_cb, timeout)` | Один вызов коннектора → статус `ok` / `failed` / `unknown` / `unavailable` |
| `_cdp_sequence(label, steps, checker, log_cb)` | Операция как цепочка вызовов. Возвращает `True`, если повторять действие клавишами не нужно |
| `_cdp_verify_or_defer(...)` / `_flush_pending_cdp_verify(log_cb)` | Проверка результата: сначала по снимкам из ответа JS, при неудаче — повторно, уже вне окна замера |
| `_cdp_click_context_item(wanted, log_cb)` | Клик по пункту раскрытого контекстного меню по его подписи — замена слепому счёту стрелок на pyautogui-пути |
| `_col_letter(index)` | 1 → A, 5 → E, 27 → AA: клавиатурная версия ходит стрелками, api адресует ячейки ссылками |

`self._op_via_cdp` (сбрасывается перед каждым замером рядом с `_op_start_grace`
и `_op_max_wait`) меняет трактовку статуса `below_floor`. На клавиатурном пути он
означает «pyautogui вернулся мгновенно, измерить нечего»; на CDP-пути
`Runtime.evaluate` возвращается только после того, как api отработал, поэтому
цифра — реальная длительность вызова, просто Р7 после него не успел стать
занятым. В лог это пишется разными строками.

Выключатель `CDP_OPS_ENABLED = False` возвращает все тесты на клавиатурный
путь — нужен, чтобы сравнить цифры двух путей на одной сборке. Цифры двух
путей между собой **несравнимы**: клавиатурный путь меряет ещё и работу
оконного менеджера, отрисовку меню и модалок.

#### Откат на клавиши разрешён не всегда

`evaluate()` возвращает `None` не только при обрыве соединения, но и когда
`Runtime.evaluate` не уложился в таймаут сокета — а он возвращается только
после того, как JS отработал, то есть после самой операции. На большом файле
`asc_EditSelectAll` или вставка идут дольше таймаута, и `None` в этот момент
означает «операция уже ушла в Р7», а не «ничего не произошло». Повторить её
клавишами значило бы применить правку дважды.

Отсюда правило: откат на pyautogui выполняется, только если документ
гарантированно не тронут. Признак — поле `mutated` в ответе JS: оно
выставляется прямо перед изменяющим документ вызовом (`asc_Paste`,
`asc_addWorksheet`, `asc_insertCells`) и не выставляется у безобидных
(`asc_EditSelectAll`, `asc_Copy`, `asc_findCell`, `asc_showWorksheet` — их
повтор ничего не портит).

Из того же правила следует требование к цепочкам: **изменяющий документ шаг
обязан быть последним**. Иначе сбой на последнем шаге застанет документ уже
изменённым, и `_cdp_sequence` вынужденно запретит откат (`mutated_already`) —
цифра прогона в этот момент уже испорчена.

#### Проверка результата и почему она отложенная

Каждая операция снимает состояние документа (`docState`: число листов,
активный лист, выделение, позиция в History) до и сразу после вызова api.
Оба снимка делаются внутри страницы и стоят доли миллисекунды — round-trip
там один, тот же самый.

Но часть операций Р7 доводит асинхронно: `asc_Paste` уходит в нативный код, и
к моменту возврата документ ещё не изменён. Поэтому неподтвердившаяся проверка
не считается провалом сразу — она откладывается в `self._pending_cdp_verify` и
доводится в `_flush_pending_cdp_verify` рядом с `_flush_pending_modal_confirm`,
то есть уже ПОСЛЕ `_wait_operation_done`. Второй round-trip в замер не попадает.

Чем проверяется:
* Ctrl+A — выделение стало полным листом. Форм записи несколько, и живая
  сборка (2026.2.2.x) отдаёт из `asc_getActiveRangeStr` именно `1:1048576` —
  диапазон СТРОК, без букв столбцов; проверка принимает также `A1:XFD1048576`
  и `A:XFD`. Порог по числу строк, а не сравнение с константой: точное число
  зависит от сборки;
* новый лист — `asc_getWorksheetsCount()` вырос ровно на 1;
* вставка и `insertCells` — сдвинулась история правок (`History.Index` /
  `Points.length` / `Can_Undo()`): универсальный признак принятой правки;
* копирование не проверяется — документ оно не меняет, а содержимое системного
  буфера из DOM не прочитать.

#### Клик по пункту меню: только по подписи и только по «новым» элементам

`click_menu_item` нужен на pyautogui-пути: меню там обходится вслепую
(`down` N раз + Enter), и лишний пункт уводит счётчик. Две вещи, без которых
им нельзя пользоваться:

1. **Точное совпадение подписи проверяется раньше вхождения подстроки** —
   иначе «Копировать формат» перехватывал бы клик, адресованный «Копировать».
2. **Из кандидатов вычитается базовый DOM-снимок** (`_capture_cdp_ui_baseline`).
   По issue #9 в дампе постоянно висит overflow-меню тулбара с такими же
   подписями, как у пунктов контекстного меню; клик по нему — это нажатие
   произвольной кнопки тулбара посреди замера.

Судя по дампам из того же issue #9, контекстное меню Р7 рисуется нативным
оверлеем CEF и в обходимом DOM не появляется — то есть неудача здесь штатная,
и вызывающий код молча продолжает стрелками.

### Размер главного окна

`_apply_default_geometry` (константы `DEFAULT_WIN_W`/`DEFAULT_WIN_H` = 1180×780) вызывается из `__init__` вместо прежнего жёсткого `geometry("800x600")`: в 800 px по ширине сетка карточек на вкладке «Производительность» (Canvas 380 px) и лог рядом с ней не помещались, и интерфейс выглядел обрезанным. Просто увеличить константу нельзя — на экране 1366×768 окно 1180×780 не влезет, поэтому желаемый размер ограничивается размером экрана минус поля под рамки и панель задач, но не опускается ниже `minsize` (760×560). Окно центрируется по горизонтали и ставится на треть высоты по вертикали. `state('zoomed')` намеренно не используется: разворачивать чужое окно на весь экран при старте — навязчиво, а пользователь всегда может сделать это сам.

### Тёмная тема

Словарь `COLORS` в начале файла — единственный источник цветов тёмной темы; `_apply_dark_theme` применяет его через `ttk.Style`. Тема `ttk` выбрана `clam` намеренно: нативные темы Windows (`vista`/`winnative`) рисуют часть виджетов средствами ОС и игнорируют цветовые переопределения `ttk.Style`, тогда как `clam` — собственный рендерер Tk с полной поддержкой кастомизации цвета. Главное окно сохраняет нативные заголовок и рамку ОС (`overrideredirect` не используется) — требование «кастомной шапки» реализовано добавленными виджетами-заголовком внутри содержимого окна, под нативным заголовком; это осознанный выбор в пользу избежания рисков самодельного безрамочного окна (перетаскивание, сворачивание/восстановление, поведение при DPI/snap), а не недосмотр.

### HTML-отчёты и PDF

PDF-экспорт реализован через браузер: кнопка `📄 Сохранить как PDF` вызывает `window.print()`. Reportlab не используется (убран из requirements.txt).

`Performance_Report_{ts}.xlsx`/`.html` в `Reports/` именуются с таймстампом — раньше имя было фиксированным, и каждый следующий прогон затирал отчёт предыдущего.

Все значения, попадающие в HTML-разметку из внешних источников (реестр, `simpledialog`, исключения, произвольные JSON-файлы результатов, добавленные через диалог выбора файла), экранируются через `html.escape()`.

| Метод | Описание |
|-------|----------|
| `_generate_html_report(...)` | Основной отчёт производительности. Содержит кнопку печати и `@media print`. |
| `_generate_batch_summary_html(...)` | Сводный отчёт Batch-режима. Содержит кнопку печати и `@media print`. |
| `_generate_comparison_html(...)` | Отчёт сравнения версий. Содержит кнопку печати и `@media print`. |
| `_json_for_script(obj, **kwargs)` | `json.dumps()`, безопасный для вставки прямо внутрь `<script>`: заменяет `</` на `<\/`, чтобы строковое значение с буквальным `</script` не закрывало тег раньше времени. Используется вместо `json.dumps` везде, где результат идёт в `<script>` во всех четырёх генераторах отчётов |

## Правила работы с кодом

### 1. Импорты
- Стандартные библиотеки: `os`, `sys`, `time`, `threading`, `json`, `csv`, `hashlib`, `subprocess`, `winreg`, `shutil`, `re`, `tempfile`, `pathlib`, `datetime`, `tkinter`, `webbrowser`
- Сторонние: `pyautogui`, `psutil`, `pyperclip`, `openpyxl`, `win32gui`, `win32con`

### 2. Координаты и разрешение экрана
- НЕ использовать жёсткие координаты (например `pyautogui.click(x=800, y=400)`)
- Использовать `pyautogui.click(button='right')` без координат, или клик по центру найденного окна
- Навигацию по листам делать через горячие клавиши (`Ctrl+PageUp`, `Ctrl+PageDown`)

### 3. Замеры времени
- Не включать `time.sleep()` внутрь измеряемых функций. Там, где Р7 не успевает за
  клавиатурой (меню, буфер обмена), использовать `self._pace(sec)` — она копит время
  в `_paced_total`, и оно вычитается из результата
- `pyautogui.PAUSE = 0` выставлен на уровне модуля и `interval` в `hotkey` не передаётся:
  умолчание 0.1 сек добавлялось после каждого вызова и составляло весь результат замера
- Секундомер операции останавливать по `_wait_operation_done`, а не на последнем нажатии:
  pyautogui возвращается сразу после отправки клавиш, не дожидаясь обработки в Р7
- Паузы вне замера выносить в `post_action_delay()` после `measure()`
- Для ожидания загрузки данных использовать `_wait_until_r7_ready` (отзывчивость окна + простой CPU).
  Прежний зонд через `Ctrl+End` удалён: `keybd_event` не дожидается обработки, поэтому его
  длительность была константой и о состоянии Р7 не говорила ничего
- Подготовку окна (разворот, фокус, снятие диалога обновления) засекать отдельно и вычитать
  из `open_elapsed` — она не относится к скорости открытия файла

### 4. Обработка ошибок
- Все вызовы `win32gui.SetForegroundWindow` оборачивать в try/except
- Таймауты для `subprocess` обрабатывать с `proc.kill()`. Для `Popen` не передавать
  `shell=True` со списком аргументов — с ним `proc.kill()` завершает промежуточный
  `cmd.exe`, а не сам процесс
- Проверять права администратора перед запуском тестов
- Не использовать голый `except:` (глотает `KeyboardInterrupt`/`SystemExit`) —
  минимум `except Exception:`
- `pyautogui.FAILSAFE = True`: инструмент не двигает курсор сам (только клики по
  текущей позиции), поэтому это ничего не ломает и даёт оператору физический
  аварийный выход — увести мышь в угол экрана

### 5. Логирование
- Использовать `add_test_log()` для вывода сообщений
- Логировать начало и конец каждой операции
- При ошибках писать в лог с префиксом "❌"
- `add_test_log` вызывается сотнями раз за прогон из фоновых потоков и использует
  `root.update_idletasks()`, а не `root.update()` — последний заходит в цикл
  обработки событий Tk и мог реентерабельно исполнить обработчик кнопки посреди
  стека фонового потока

### 6. UI
- Не блокировать главный поток длительными операциями — использовать `threading`
- Обновлять UI через `root.after(0, callback)` — обязательно для любого кода,
  который может выполниться не из главного потока (детект версии, статус
  установки и т.п.)
- Прогресс-бары и статус-бар должны обновляться
- Перед запуском теста/Batch-режима проверять `self._perf_running`/`self._batch_running`
  и блокировать повторный/перекрёстный запуск — оба режима одновременно шлют клавиши
  в Р7-Офис. `self.perf_stop_event` — способ прервать прогон между операциями
  (кнопка «⏹ Остановить» на вкладке «Производительность»); Р7 при этом закрывается
  штатно и отчёт по выполненным операциям сохраняется
- Модальные диалоги (`tk.Toplevel`) создавать с `.transient(self.root)` — иначе
  диалог может потеряться за главным окном

## Примечания
- Р7-Офис в диспетчере задач называется `editors_helper.exe`
- Процесс может называться также `DesktopEditors.exe` или `Р7-Офис`
- Реальный путь: `...\R7-Office\Editors\DesktopEditors.exe` (без вложенной папки `DesktopEditors\`)
- При добавлении/переименовании места, где формируется имя `.xlsx`-файла, следить за
  двойным расширением `.xlsx.xlsx` — на момент этой записи оба места (`compare_file_sizes`)
  уже проверяют `endswith(".xlsx")` перед добавлением суффикса
- Поиск процессов Р7 (`_get_r7_processes`, `_R7_PROCESS_NAMES`) сознательно не включает
  голые подстроки "r7"/"р7" — под них попадают и собственные сборки инструмента
  (R7-Testovarka.exe, R7Manager.exe), искажая замеры RAM/CPU
- Координаты для кликов определяются динамически через центр активного окна
