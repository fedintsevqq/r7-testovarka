# Запасные пути тестов через интерфейс Р7

Проверено на живом Р7 2026.3.2 30.09.2026, фикстура 50К.

## Почему это всплыло

Отчёт прогона 30.09.2026 15:02: все операции длились миллисекунды со статусом
«ниже порога», а готовность документа определилась по CPU, не по кнопке
«Жирный». Программа была запущена двойным щелчком по `.py`, то есть через
`py.exe` и системный Python 3.14. В нём нет `requests`, `websocket-client` и
`pywinauto`, поэтому CDP был выключен. Дальше цепочка такая:

1. Модалка «Автоматический пересчёт может занять время» — HTML, окна ОС у неё
   нет. CPU при ней простаивает, и готовность объявлялась при пустой сетке.
2. Клавиши тестов уходили в модалку. Первый Enter из теста ПКМ нажимал
   кнопку по умолчанию «Да» и включал ручной пересчёт.
3. Запасные пути тестов правки в этой сборке не работали вовсе (ниже).

Из `.venv` тот же код прошёл все 12 операций через api без единого меню.

## Что устроено в Р7 2026.3.2

**Контекстное меню ячейки есть в DOM** (вывод issue #9 о нативном оверлее
CEF для этой сборки неверен): `.dropdown-menu > li > a`, пункты с «▸» —
`li.dropdown-submenu` со своим `.dropdown-menu`, скрытым до наведения.

- Пункты: Вырезать, Копировать, **Вставить ▸** (Вставить, Вставить только
  формулу, … Специальная вставка), **Добавить ▸** (Ячейки со сдвигом вправо,
  Ячейки со сдвигом вниз, Строку, Столбец), Удалить ▸, …
- На листе с автофильтром сдвиги ячеек недоступны (`disabled`).
- Стрелки клавиатуры меню не двигают — ни после Shift+F10, ни после правого
  клика. Слепой обход «down N раз + Enter» не работал никогда в этой сборке.
- Shift+F10 открывает меню у выделения. `pyautogui.click(button='right')` без
  координат кликал туда, где стоит мышь, и сбрасывал выделение.
- Клик по пункту — `R7WebDriverConnector.click_context_menu_path(path)`:
  подпись сравнивается точно («Вставить» ≠ «Вставить только формулу»),
  подменю раскрывается событием `mouseenter`, клик откладывается
  `setTimeout`, чтобы работа Р7 не попала в round-trip, который вычитается
  из замера.
- Пока меню открыто, следующий Shift+F10 теряется. `_context_menu_pick` ждёт,
  пока меню закроется (`context_menu_open`).

**Диалог «Вставить ячейки»** (Ctrl+Shift+= на одной ячейке): `.asc-window.modal`
с переключателями `asc-radio-opt-dlg` (сдвиг вправо / вниз / строку / столбец)
и кнопками `result="ok"`/`"cancel"`. По умолчанию выбран сдвиг вправо —
прежний код на этом останавливался, и столбец не вставлялся.

- Стрелки переключатель не двигают. Tab — к следующему варианту, пробел —
  выбрать, Enter — OK.
- Фокус приходит в диалог через 0.1–0.15 с после появления; Tab раньше уходят
  в сетку (так упал первый живой прогон). `insert_cells_dialog_state` отдаёт
  `focused` и `choice`.

**Alt+I** в этой сборке ничего не открывает, и следующая «c» начинала правку
ячейки. Тест «Добавление столбца (меню Вставка)» теперь идёт через «Добавить ▸
Столбец» контекстного меню.

**Модалка пересчёта** (`onHeavyCalculationWarning` в `app.js`): любой ответ,
кроме «Да», — автоматический пересчёт. Esc закрывает её именно так
(`calcPr.calcMode` не выставлен). Без CDP `_wait_until_r7_ready` на первом
простое шлёт Esc (только в окно Р7 на переднем плане) и ждёт ещё одну серию
простоя: Р7 занялся работой — модалка была, ожидание ответа вычитается,
маркер `cpu_esc`; не занялся — модалки не было, готовность — первый простой.

## Итог живых прогонов

| Режим | Результат |
|---|---|
| CDP, операции через api | 12/12, как раньше |
| CDP есть, `CDP_OPS_ENABLED = False` | столбец через диалог и через меню, ПКМ 1 и 5 ячеек — все с изменением документа |
| Без CDP | модалка закрыта Esc, Ctrl+A 1.64 с (было 0.002), столбец через диалог 2.4 с; ПКМ и «меню» — понятная ошибка вместо слепых нажатий |

Цифры клавиатурного пути с api-путём несравнимы (см. `docs/cdp-operations.md`).
