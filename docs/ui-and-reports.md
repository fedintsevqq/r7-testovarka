#### Живой набор `tests/live/` (маркер `live`)

Запускает Р7 один раз на модуль, на фикстуре, сгенерированной `_generate_fixture` во временной папке (файлы `TestFiles/` не трогает). Проверяет открытие, все CDP-операции, экспорт pdf/ods/xltx/csv через `_save_as_format` до файла на диске и `_emergency_close_r7`. Без `R7_LIVE=1` пропускается целиком, обычный `pytest -q` его не гоняет. `SKIP:` от `_save_as_format` (диалог не открылся) помечается `xfail`, не падением.

```bash
R7_LIVE=1 .venv/Scripts/python.exe -m pytest -m live tests/live -v
```

Подтверждено на Р7 2026.3.2 (29.09.2026): 7/7, около 1 мин, все четыре формата дошли до диска, процессов после закрытия не осталось.

CI: `tests.yml` гоняет матрицу Python 3.11/3.14 под `coverage run --branch` (отчёт покрытия информационный, порога нет). `perf.yml` теперь сам генерирует `test_10k.xlsx` (раньше на чистом раннере файла не было — `*.xlsx` не коммитятся) и дополнительно запускает живой набор; сам workflow по-прежнему не проверен на self-hosted раннере.

### Размер главного окна

`_apply_default_geometry` вызывается в конце `__init__`, ПОСЛЕ `setup_ui`: размер берётся из того, что собранному интерфейсу реально нужно (`winfo_reqwidth/height`), но не меньше `DEFAULT_WIN_W`×`DEFAULT_WIN_H` (1220×780). Раньше константа ставилась до сборки, и на экране с масштабом 125–150% (шрифты крупнее) низ вкладки с кнопкой «Запустить» обрезался. Окно вписывается в рабочую область без панели задач (`_work_area`, `SPI_GETWORKAREA`; `winfo_screenheight` включает панель задач) и центрируется. Расчёт — чистая `_fit_window(need_w, need_h, area)`, на неё есть тесты. `state('zoomed')` включается только если интерфейс не помещается даже в рабочую область. `minsize` — `MIN_WIN_W`×`MIN_WIN_H` (820×560): при нём всё работает, тест `test_run_button_visible_at_minimum_size`.

Правило раскладки: нижние панели (кнопки, строка статуса) упаковываются ПЕРВЫМИ с `side=BOTTOM`. Упаковщик раздаёт место в порядке упаковки, и при низком окне обрезается последний виджет — раньше это были именно кнопки. Растягиваемое содержимое (список, таблица, лог) упаковывается последним и имеет свою прокрутку.

### Вкладка «Производительность» (29.09.2026)

* Слева список тестов по группам (`_test_groups`: открытие, операции, экспорт), справа лог; граница перетаскивается (`ttk.Panedwindow`). Щелчок по названию теста или по заголовку группы включает/выключает; выключенные тесты серые.
* Число повторов — `_make_runs_control`: «−» [N] «+» вместо `ttk.Spinbox` (стрелки по 8 px, принимал любой текст, пустое поле роняло `IntVar.get()` при запуске). Ввод только цифр, `_clamp_runs` прижимает к `RUNS_MIN..RUNS_MAX` (1–20), ↑/↓ в поле. «Повторов у отмеченных» + «Применить» — одно число всем отмеченным.
* Колесо мыши над списком — `_bind_wheel`: привязка на каждом виджете списка, не `bind_all`. Диалоги при закрытии зовут `unbind_all("<MouseWheel>")`, а схема `bind_all` на `<Enter>`/`unbind_all` на `<Leave>` (так было в списке версий Batch) отключала прокрутку, как только курсор заходил на строку.
* Выбор сохраняется сам через 0.8 с после изменения (`_on_test_selection_changed`), а не только по «Запустить». При сборке списка не сохраняется (`_building_test_list`).
* Под списком сводка «Отмечено N из M · всего повторов»; «Запустить» недоступна, если ничего не отмечено. Индикатор в шапке — «Готов» / «Идёт прогон» / «Идёт Batch-режим» (`_set_busy_indicator`).
* Лог: перенос по словам, только чтение с клавиатуры (копировать можно), кнопки «Очистить» и «Папка отчётов», подсказка «как запустить» до первого сообщения.
* Шапка в одну строку, версия — `_short_version_text` без «(десктопная версия)»: на узком окне обрезался номер сборки.

Диалоги: `_on_toplevel_map` (класс-привязка `Toplevel <Map>`) переносит в центр главного окна диалог, который Windows открыл в углу экрана; `_center_dialog` — то же явно. Тесты — `tests/test_ui_usability.py` (на настоящем окне Tk, скрытом).

### Тема оформления

ttk-виджеты рисует тема Sun Valley (пакет `sv-ttk`, вид Windows 11) — тёмная или
светлая, переключатель в шапке (`_toggle_theme`), выбор хранится в `ui_settings.json`.
Нет пакета — прежняя тёмная тема на `clam` (`_configure_clam`).

Цвета — палитры `PALETTES` в `r7/ui/base.py`; `COLORS` — текущая, модули берут её
при создании виджетов. Виджеты Tk вне ttk (журнал, холсты, меню) тема не трогает:
`_recolor_tk_widgets` перекрашивает их при смене темы. Ловушка: sv-ttk на
`<<ThemeChanged>>` зовёт `tk_setPalette`, тот вписывает цвет текста в базу опций и в
уже созданные виджеты, и ttk-надписи переставали брать цвет из своего стиля. Поэтому
`*TLabel.foreground` и подобные очищены в базе опций, а `_on_theme_changed` после
события возвращает цвета (`_clear_ttk_foreground`). Цвет надписи задаётся стилем
(`Secondary.TLabel`, `VersionOk.TLabel` …), а не `foreground=` — иначе он не сменится
с темой; намеренно свой цвет помечается `_r7_fg`.

Значки — глифы шрифта Segoe MDL2 Assets, нарисованные Pillow (`r7/ui/icons.py`), один
стиль и размер вместо эмодзи; кнопка со значком — `_icon_button`, у недоступной кнопки
приглушённая картинка (`image=(img, "disabled", dim)`). Журнал раскрашен по первому
значку сообщения (`_log_tag`): ❌ ошибка, ⚠ предупреждение, ✅/🏁 успех, 📊/⏱ итог.

Главное окно сохраняет нативные заголовок и рамку ОС (`overrideredirect` не
используется): самодельное безрамочное окно ломает перетаскивание, сворачивание и
поведение при DPI/snap.

### HTML-отчёты и PDF

PDF-экспорт реализован через браузер: кнопка `📄 Сохранить как PDF` вызывает `window.print()`. Reportlab не используется (убран из requirements.txt).

`Performance_Report_{ts}.xlsx`/`.html` в `Reports/` именуются с таймстампом — раньше имя было фиксированным, и каждый следующий прогон затирал отчёт предыдущего.

Все значения, попадающие в HTML-разметку из внешних источников (реестр, `simpledialog`, исключения, произвольные JSON-файлы результатов, добавленные через диалог выбора файла), экранируются через `html.escape()`.

| Метод | Описание |
|-------|----------|
| `_generate_html_report(...)` | Основной отчёт производительности. Содержит кнопку печати и `@media print`. |
| `_generate_batch_summary_html(...)` | Сводный отчёт Batch-режима. Содержит кнопку печати и `@media print`. |
| `_generate_comparison_html(...)` | Отчёт сравнения версий. Содержит кнопку печати и `@media print`. |
| `_json_for_script(obj, **kwargs)` | `json.dumps()`, безопасный для вставки прямо внутрь `<script>`: заменяет `</` на `<\/`, чтобы строковое значение с буквальным `</script` не закрывало тег раньше времени. Используется вместо `json.dumps` везде, где результат идёт в `<script>` во всех четырёх генераторах отчётов |
