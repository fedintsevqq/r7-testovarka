#### Живой набор `tests/live/` (маркер `live`)

Запускает Р7 один раз на модуль, на фикстуре, сгенерированной `_generate_fixture` во временной папке (файлы `TestFiles/` не трогает). Проверяет открытие, все CDP-операции, экспорт pdf/ods/xltx/csv через `_save_as_format` до файла на диске и `_emergency_close_r7`. Без `R7_LIVE=1` пропускается целиком, обычный `pytest -q` его не гоняет. `SKIP:` от `_save_as_format` (диалог не открылся) помечается `xfail`, не падением.

```bash
R7_LIVE=1 .venv/Scripts/python.exe -m pytest -m live tests/live -v
```

Подтверждено на Р7 2026.3.2 (29.09.2026): 7/7, около 1 мин, все четыре формата дошли до диска, процессов после закрытия не осталось.

CI: `tests.yml` гоняет матрицу Python 3.11/3.14 под `coverage run --branch` (отчёт покрытия информационный, порога нет). `perf.yml` теперь сам генерирует `test_10k.xlsx` (раньше на чистом раннере файла не было — `*.xlsx` не коммитятся) и дополнительно запускает живой набор; сам workflow по-прежнему не проверен на self-hosted раннере.

### Размер главного окна

`_apply_default_geometry` вызывается в конце `__init__`, ПОСЛЕ `setup_ui`: размер берётся из того, что собранному интерфейсу реально нужно (`winfo_reqwidth/height`), но не меньше `DEFAULT_WIN_W`×`DEFAULT_WIN_H` (1220×780). Раньше константа ставилась до сборки, и на экране с масштабом 125–150% (шрифты крупнее) низ вкладки с кнопкой «Запустить» обрезался. Окно вписывается в рабочую область без панели задач (`_work_area`, `SPI_GETWORKAREA`; `winfo_screenheight` включает панель задач) и центрируется. Расчёт — чистая `_fit_window(need_w, need_h, area)`, на неё есть тесты. `state('zoomed')` включается только если интерфейс не помещается даже в рабочую область. `minsize` — `MIN_WIN_W`×`MIN_WIN_H` (820×560): при нём всё работает, тест `test_run_button_visible_at_minimum_size`.

Правило раскладки: нижние панели (кнопки, строка статуса) упаковываются ПЕРВЫМИ с `side=BOTTOM`. Упаковщик раздаёт место в порядке упаковки, и при низком окне обрезается последний виджет — раньше это были именно кнопки. Растягиваемое содержимое (список, таблица, лог) упаковывается последним и имеет свою прокрутку.

### Вкладка «Производительность» (29.09.2026)

* Слева список тестов по группам (`_test_groups`: открытие, операции, экспорт), справа лог; граница перетаскивается (`ttk.Panedwindow`). Щелчок по названию теста или по заголовку группы включает/выключает; выключенные тесты серые.
* Число повторов — `_make_runs_control`: «−» [N] «+» вместо `ttk.Spinbox` (стрелки по 8 px, принимал любой текст, пустое поле роняло `IntVar.get()` при запуске). Ввод только цифр, `_clamp_runs` прижимает к `RUNS_MIN..RUNS_MAX` (1–20), ↑/↓ в поле. «Повторов у отмеченных» + «Применить» — одно число всем отмеченным.
* Колесо мыши над списком — `_bind_wheel`: привязка на каждом виджете списка, не `bind_all`. Диалоги при закрытии зовут `unbind_all("<MouseWheel>")`, а схема `bind_all` на `<Enter>`/`unbind_all` на `<Leave>` (так было в списке версий Batch) отключала прокрутку, как только курсор заходил на строку.
* Выбор сохраняется сам через 0.8 с после изменения (`_on_test_selection_changed`), а не только по «Запустить». При сборке списка не сохраняется (`_building_test_list`).
* Под списком сводка «Отмечено N из M · всего повторов»; «Запустить» недоступна, если ничего не отмечено. Индикатор в шапке — «Готов» / «Идёт прогон» / «Идёт Batch-режим» (`_set_busy_indicator`).
* Лог: перенос по словам, только чтение с клавиатуры (копировать можно), кнопки «Очистить» и «Папка отчётов», подсказка «как запустить» до первого сообщения.
* Шапка в одну строку, версия — `_short_version_text` без «(десктопная версия)»: на узком окне обрезался номер сборки.

Диалоги: `_on_toplevel_map` (класс-привязка `Toplevel <Map>`) переносит в центр главного окна диалог, который Windows открыл в углу экрана; `_center_dialog` — то же явно. Тесты — `tests/test_ui_usability.py` (на настоящем окне Tk, скрытом).

### Редактор на вкладке «Производительность» (08.10.2026)

Раньше документы и презентации запускались только из CLI (`python -m r7 run --suite suites/docs.toml|slides.toml`). Теперь над списком тестов — переключатель «Таблица (.xlsx) / Документ (.docx) / Презентация (.pptx)»: три `ttk.Radiobutton` в стиле `Toolbutton` (в sv-ttk это сегменты, выбранный подсвечен). Подписи и воркеры — `r7/editors.py` (`EDITOR_LABELS`, `EDITOR_WORKERS`; CLI берёт тот же словарь воркеров).

* Смена редактора (`_on_perf_editor_selected`) сначала сохраняет выбор прежнего, потом пересобирает строки списка (`_fill_test_rows`): тесты редактора (`_tab_test_names`), группы с заголовком «ОПЕРАЦИИ В ТАБЛИЦЕ / ДОКУМЕНТЕ / ПРЕЗЕНТАЦИИ», повторы по умолчанию — `DEFAULT_DOC_RUNS` и `DEFAULT_PPTX_RUNS` (5, экспорт 3). Плагины (`plugins/*.py`) — только у таблиц.
* Выбранный на вкладке редактор — `_perf_editor`. Это не `_run_editor`: тот — режим идущего прогона, его ставят `_document_worker` и `_presentation_worker`.
* «Запустить» зовёт воркер редактора через тот же `_start_run(PERF, …)`: `run_state.try_start`, `perf_stop_event`, шкала, «Остановить», диалог после теста — общие. Пока идёт прогон, переключатель недоступен (`_set_editor_selector_state`), после — снова доступен.
* Под переключателем — какой файл откроет прогон (`_perf_fixture_hint`). Таблица — рабочая фикстура, её создаёт окно «Тестовые файлы»; не найдена — подсказка об этом. Документ и презентация — `r7-test-doc-100p.docx` и `r7-test-slides-50.pptx`; если файла нет, воркер создаёт его сам в TestFiles при запуске. Кнопка «Тестовые файлы» — только про таблицы.

`selected_tests.json` теперь по редакторам (`r7/test_selection.py`):

```json
{"_editor": "document",
 "spreadsheet": {"Ctrl+A": {"enabled": true, "runs": 7}},
 "document": {"Поиск и замена": {"enabled": false, "runs": 5}},
 "presentation": {}}
```

Читаются все три формата: `{тест: bool}`, плоский `{тест: {"enabled", "runs"}}` (это выбор таблиц, его же пишет `suite_to_selection` в `r7/suites.py`) и по редакторам. Битый файл — значения по умолчанию. Пишется только формат по редакторам: выбор других редакторов при сохранении остаётся как был. Окно открывается на редакторе из `"_editor"` (`_saved_perf_editor`); в юнит-тестах `conftest` подменяет его на таблицу, чтобы файл пользователя не влиял на тесты окна. Тесты — `tests/test_ui_perf_editors.py`.

### Тема оформления

ttk-виджеты рисует тема Sun Valley (пакет `sv-ttk`, вид Windows 11) — тёмная или
светлая, переключатель в шапке (`_toggle_theme`), выбор хранится в `ui_settings.json`.
Нет пакета — прежняя тёмная тема на `clam` (`_configure_clam`).

Цвета — палитры `PALETTES` в `r7/ui/base.py`; `COLORS` — текущая, модули берут её
при создании виджетов. Виджеты Tk вне ttk (журнал, холсты, меню) тема не трогает:
`_recolor_tk_widgets` перекрашивает их при смене темы. Ловушка: sv-ttk на
`<<ThemeChanged>>` зовёт `tk_setPalette`, тот вписывает цвет текста в базу опций и в
уже созданные виджеты, и ttk-надписи переставали брать цвет из своего стиля. Поэтому
`*TLabel.foreground` и подобные очищены в базе опций, а `_on_theme_changed` после
события возвращает цвета (`_clear_ttk_foreground`). Цвет надписи задаётся стилем
(`Secondary.TLabel`, `VersionOk.TLabel` …), а не `foreground=` — иначе он не сменится
с темой; намеренно свой цвет помечается `_r7_fg`.
Событие Tk шлёт каждому виджету, а привязка на корне ловит все: обход дерева
`_on_theme_changed` ставит один на пачку событий (`_theme_fix_pending`). Без
склейки было ~200 полных обходов, O(n²): 0,5 с из 0,9 с создания окна.
Кнопки со значками закрытых окон `_refresh_icons` выкидывает из списка.

Значки — глифы шрифта Segoe MDL2 Assets, нарисованные Pillow (`r7/ui/icons.py`), один
стиль и размер вместо эмодзи; кнопка со значком — `_icon_button`, у недоступной кнопки
приглушённая картинка (`image=(img, "disabled", dim)`). Журнал раскрашен по первому
значку сообщения (`_log_tag`): ❌ ошибка, ⚠ предупреждение, ✅/🏁 успех, 📊/⏱ итог.
Каждая строка журнала, необработанные исключения потоков и ошибки внутри обработчиков
Tk (`_on_tk_callback_error`, окно не чаще раза в 5 с) пишутся и в файл
`Reports/logs/r7-testovarka.log` (`r7/logfile.py`, ротация 5 МБ × 5, в начале — версия,
Python и стенд); жёсткое падение интерпретатора оставляет стек в `Reports/logs/crash.log`.

Главное окно сохраняет нативные заголовок и рамку ОС (`overrideredirect` не
используется): самодельное безрамочное окно ломает перетаскивание, сворачивание и
поведение при DPI/snap.

### HTML-отчёты и PDF

PDF-экспорт реализован через браузер: кнопка `📄 Сохранить как PDF` вызывает `window.print()`. Reportlab не используется (убран из requirements.txt).

`Performance_Report_{ts}.xlsx`/`.html` в `Reports/` именуются с таймстампом — раньше имя было фиксированным, и каждый следующий прогон затирал отчёт предыдущего.

Все значения, попадающие в HTML-разметку из внешних источников (реестр, `simpledialog`, исключения, произвольные JSON-файлы результатов, добавленные через диалог выбора файла), экранируются через `html.escape()`.

| Метод | Описание |
|-------|----------|
| `_generate_html_report(...)` | Основной отчёт производительности. Содержит кнопку печати и `@media print`. |
| `_generate_batch_summary_html(...)` | Сводный отчёт Batch-режима. Содержит кнопку печати и `@media print`. |
| `_generate_comparison_html(...)` | Отчёт сравнения версий. Содержит кнопку печати и `@media print`. При 3+ версиях графики RAM и CPU идут на всю ширину друг под другом (`stack-charts`); таблица прокручивается внутри (`table-wrap scroll`) с закреплённой шапкой и колонками «Операция» и «Порог», в печати раскрывается целиком. |
| `_json_for_script(obj, **kwargs)` | `json.dumps()`, безопасный для вставки прямо внутрь `<script>`: заменяет `</` на `<\/`, чтобы строковое значение с буквальным `</script` не закрывало тег раньше времени. Используется вместо `json.dumps` везде, где результат идёт в `<script>` во всех четырёх генераторах отчётов |

### Сборка Р7, отпечаток машины и общая папка (07.10.2026, этап 2 плана)

Полный JSON получил два блока метаданных. Схема замера от них не зависит, поэтому
`MEASURE_SCHEMA_VERSION` не поднимался (правило 11 `CLAUDE.md`); все читатели терпят
отчёты без этих ключей.

* **`build`** (`r7/build_meta.py`, пишет `_build_metadata`): `product`, `version`,
  `build_number` (последний числовой компонент версии), `installer_file` (имя
  дистрибутива, если версию ставил Batch в этой сессии и она ещё установлена; установка
  с вкладки «Версии» не запоминается), `exe_path`, `exe_mtime`, `exe_size`, `exe_sha256`
  DesktopEditors.exe, `changelog_url` по шаблону `changelog_url_template` из
  `r7_settings.json` (поля `{version}`, `{build}`). Хэш exe (~50 МБ) считается один раз
  за запуск (кэш по пути, mtime и размеру) и только до секундомера: в трёх путях
  запуска перед `_wait_system_quiet`. В HTML — блок «Стенд» (сборка, sha256 коротко,
  дата exe), в сравнении — номер сборки под именем версии и колонки «Сборка»/«Машина»
  в таблице стендов.
* **`system.environment.fingerprint`** и **`fingerprint_hash`** (`r7/fingerprint.py`,
  собирает `_machine_fingerprint` из `_capture_environment`): модель CPU, число ядер,
  RAM (до ГБ), ОС, масштаб экрана, диск с данными Р7 (`%LOCALAPPDATA%`), диск отчётов,
  план питания; хэш — 12 hex sha256 канонического JSON. Сравнение, тренды и
  `nightly.compare_reports` считают разные хэши «другим стендом»: на страницах такое же
  предупреждение, как про разные схемы, с перечнем отличий; в ночном контуре регрессия
  не становится тревогой (`block_reason` → «другой стенд»). Отчёты без отпечатка чужими
  не считаются.
* **`system.environment.calibration`** (`r7/calibration.py`, `_calibrate_stand`):
  `cpu_ms` — медиана трёх прогонов фиксированного цикла на чистом Python, `disk_mb_s` —
  запись 64 МБ с fsync и чтение обратно в папке отчётов. Идёт один раз на прогон внутри
  `_capture_environment`: после секунды замера фоновой загрузки и до
  `_wait_system_quiet`, так что в открытие файла не попадает. Сбой — `None`, одна строка
  в журнал. В HTML — «Индекс стенда» в блоке «Стенд» и в таблице стендов сравнения.
* **Общая папка команды** (`r7/team_folder.py`, ключ `team_reports_folder`): после
  записи полного JSON (вкладка и Batch) он и HTML копируются в подпапку
  `<hostname>-<fingerprint_hash>`; недоступная папка — строка в журнал. Тренды
  (`_load_trends_runs`) и список сравнения (`compare_files.scan_reports`) читают оттуда
  `performance_full_*.json` из всех подпапок, помечая `machine` именем подпапки; файл с
  тем же именем, что локальный, второй раз не берётся. На странице трендов —
  предупреждение «отчёты с разных машин», колонка «Машина» в таблицах и фильтр по машине
  (JS на странице, графики перестраиваются как при смене темы); локальные отчёты
  подписаны «эта папка».

### База из K ночей, точки смены на трендах, A-B-A в Batch (07.10.2026, этап 3 плана, п. 4–5)

Формат полного JSON не менялся, схема осталась 9. Старые отчёты и сводки Batch
рисуются как раньше: нет точек смены — нет отметок, нет ключа `aba` — нет блока.

* **Ночная база** (`r7/nightly.py`). `baseline_reports(folder, current, k=5)` берёт
  последние K ночных отчётов того же режима (quick/full), той же схемы и того же стенда
  (хэш отпечатка совпадает или его нет у одного из двух — как в `block_reason`).
  `pooled_baseline` сводит их в один отчёт-базу: по операции повторы всех ночей
  склеиваются (только действительные, как в `valid_runs`), «было» — медиана медиан
  ночей. Почему так, а не медиана медиан для вердикта: при K = 5 у `compare_runs` было
  бы ровно пять точек и пропал бы разброс внутри ночи; склеенная выборка сама содержит
  разброс от ночи к ночи, и одна шумная ночь в ней весит 1/K. Критерий и порог — те же
  `compare_runs` и `compare_reports`, внутрь которых изменения не лезут
  (`compare_with_baseline`). `tests/nightly_local.py` сравнивает с базой
  (`--baseline-k`, по умолчанию 5); сравнимых ночей нет — как раньше, с прошлой ночью
  того же режима, и сводка называет причину блокировки. `previous_report` оставлен.
* **Точки смены на трендах** (`r7/changepoint.py`). Круговая бинарная сегментация с
  ранговой CUSUM и перестановочным p (499 перестановок с досрочной остановкой, зерно
  фиксировано — ответ воспроизводим), минимум 3 точки в сегменте, сдвиг медиан меньше
  5 % не отмечается; положение границы уточняется по самим значениям (минимум суммы
  отклонений от медиан). «Отрезок», а не только разрез, ловит ступеньку туда и
  обратно. На синтетике: ложные отметки на ровном ряде с CV 5 % — около 5 %, сдвиг
  10 % при CV 3 % на 10 + 10 точках находится в 96 % случаев.
  `r7_reports.mark_shifts` режет ряд операции по машине (ключ фильтра на странице) и по
  схеме замера: поперёк смены стенда или схемы сдвиг не ищется. На графике — пунктир
  у первой точки нового уровня с подписью «сдвиг с 2026.3.2.3229, +8 %» (красный —
  медленнее, зелёный — быстрее), над графиком — те же подписи плашками (фильтр машины
  прячет чужие), в таблице прогонов — колонка «Сдвиг».
* **Сэндвич A-B-A в Batch** (`r7/aba.py`, `_batch_worker(..., aba=True)`). Порог у
  операции — её порог из профиля шума стенда (`noise.threshold_for`, как у сравнения и
  бисекта), без профиля — 10 %; он же в строке сравнения (`threshold_pct`). Живой Batch
  08.10.2026 (3.2 → 3.1 → 3.2) с порогом 10 % объявил дрейф по XLTX: x2t конвертирует то
  за 5, то за 11 с, A1 и A2 разошлись на −25 % при пороге по шуму 49 %. Галочка
  «Повторить базовую версию в конце (A-B-A)» в диалоге Batch, по умолчанию включена при
  двух и более дистрибутивах; при одной выбранной версии `validate_batch_config`
  сбрасывает её. База — первая версия списка. После всех версий она ставится и меряется
  ещё раз тем же путём (`_batch_version_step` → `_batch_run_single_version`); после
  «Стоп» или остановки по ошибке повтора нет. `check_drift` сравнивает A1 и A2 по
  операциям: `compare_runs` дал РЕГРЕССИЯ/УСКОРЕНИЕ — дрейф; повторов на критерий мало
  (экспорт — 3), но с каждой стороны хотя бы два — дрейф, если медианы разошлись больше
  порога; одиночное открытие файла не сравнивается (на медленном диске стенда оно гуляет
  само). Итог — ключ `aba` у записи повтора (`aba_repeat: True`, версия с суффиксом
  «(повтор A)»). Сводка Batch (`aba_model`): красная плашка «Стенд дрейфовал за время
  Batch, сравнение ненадёжно» и таблица A в начале / A в конце; без дрейфа — зелёная
  строка; повтор не удался — жёлтая «дрейф стенда не проверен».
* **Редактор в Batch** (08.10.2026). В диалоге Batch — переключатель редактора с
  подписями вкладки «Производительность» (`r7.editors.EDITOR_LABELS`), по умолчанию —
  редактор, выбранный на вкладке. Смена подставляет фикстуру редактора
  (`batch_config.default_test_file`); у документа и презентации её нет — она создаётся
  при «Запустить» (`_batch_editor_fixture` → `_locate_test_file`). `validate_batch_config`
  отказывает, если тип файла не тот («Файл не того типа»). `_batch_worker(..., editor=…)`
  ставит режим на весь Batch, включая повтор A (`editor_mode`), операции —
  `_make_run_ops`, повторы — `_batch_runs_for` (экспорт — `DEFAULT_FORMAT_TEST_RUNS`,
  правки — `BATCH_TEST_RUNS`). Итог версии и полный JSON несут `editor`; сводка Batch
  (`batch_model`) пишет редактор в заголовке и подзаголовке и прячет колонку и график
  ВПР. Страница таблиц не изменилась (эталон `tests/fixtures/golden/batch.html`).

### Вкладка «Сценарии» (07.10.2026)

Третья вкладка главного окна (`r7/ui/scenarios_tab.py`, `ScenariosTabMixin`) запускает из
окна то, что раньше жило только в `r7/scenarios.py` и CLI: три карточки с параметрами, у
каждой своя «Запустить», одна общая «Остановить» и строка итога под карточкой. Ход
сценария идёт в общий журнал прогона (вкладка «Производительность» и файл журнала),
итог — в `Reports/scenario_<вид>_<время>.json` (`kind`, `timestamp`, `version`,
`tool_version`, `params`, `result`).

| Карточка | Что делает | Остановка |
|---|---|---|
| **Долгий прогон (soak)** | Открывает рабочую фикстуру, как вкладка «Производительность» (`_launch_r7` → готовность → `_prepare_cdp_session`), и крутит выбранную операцию правки через `run_soak`. Итерация — `_measure_op_repeated` с одним повтором: подготовка вне замера, конец по ответу редактора, откат правки, поэтому документ не растёт. Время в минутах или число итераций (0 — по времени), контрольный замер каждые N итераций. Семплер ресурсов — `ResourceSampler`; в итоге дрейф (`compare_runs` первых пяти контрольных замеров против остальных) и вердикт `detect_leak` | между итерациями (`stop_event` читают `run_soak` и замер) |
| **Много документов (multidoc)** | 2–6 фикстур по 10K строк в `TestFiles/scenarios/scenario_doc_<i>.xlsx` (создаются при первом запуске, `_generate_fixture` с разными seed), один Р7, по N операций «новый лист» на документ параллельно (`run_multidoc`). Итог: открыто файлов, выполнено операций, ошибки по файлам | между операциями над документом (открытие файлов не прерывается) |
| **Восстановление после падения** | `r7.crash_recovery.run_recovery_check`: N правок → `kill` всех процессов Р7 → перезапуск с тем же файлом → диалог «Обнаружен файл блокировки…» (UIA → CDP → win32) → подсчёт восстановленного → уборка lock-файлов и записи в `recover`. Вердикт «Успешно»/«Ошибка» по `verdict_ok` | нет: сценарий короткий, а убитый Р7 должен быть перезапущен и закрыт |

Запуск — только через `_start_run(SCENARIO, …)`: `r7/run_state.py` получил вид прогона
`SCENARIO`, взаимно исключённый с прогоном вкладки, Batch, тестом своего файла и
установкой версии (сценарии запускают и убивают процесс Р7 и делят с прогонами CDP-порт).
Перед стартом в главном потоке: CDP доступен (`WEBDRIVER_OK`), Р7 закрыт
(`_running_r7_pids`), путь к Р7 найден. Права администратора не нужны. Р7 закрывается при
любом исходе: soak — `_close_r7_gracefully` и `_emergency_close_r7`, multidoc —
`WM_CLOSE` окну и `_kill_r7_processes_since` для остатков, crash — внутри
`run_recovery_check`. Общий код сценария сбоя (правки по типу документа, поиск диалога,
проверка, уборка, отчёт) переехал из `run_crash_recovery.py` в `r7/crash_recovery.py`;
CLI реэкспортирует имена.

Тесты — `tests/test_ui_scenarios.py` (на скрытом Tk, функции сценариев и запуск Р7
подменены) и `tests/test_run_state.py` (исключение с прогонами). Живой прогон трёх
сценариев из окна на Р7 2026.3.2 ещё не делался.

### Пакет улик (07.10.2026)

Кнопка «Пакет улик» в окне «Сравнение версий» (доступна при ровно двух отмеченных
отчётах) собирает `Reports/evidence/evidence_<время>.zip` — всё, что нужно разработчику
Р7 для тикета о регрессии, без ручной сборки, как это делалось для
`Reports/bugreport_x2t_ods/`. База — выбранная в списке базы, если она среди отмеченных,
иначе первый отмеченный. Сборка идёт в фоновом потоке (не прогон Р7, `RunState` не
захватывается), затем окно с путём и открытие папки.

Внутри архива (`r7/evidence.py`, без Tk):

| Файл | Что |
|---|---|
| два `performance_full_*.json` | отчёты как есть (при одинаковых именах — префиксы `base_`/`cur_`) |
| `comparison.html` | свежая страница сравнения, тот же `_generate_comparison_html` |
| `environment.json` | версия, сборка, время, инструмент, схема, `system` и `summary` обоих отчётов рядом |
| `r7-testovarka.tail.log` | последние 2000 строк `Reports/logs/r7-testovarka.log` (нет файла — пометка в тикете) |
| `ticket.md` | готовый текст тикета (копия кладётся рядом с архивом) |

Тикет: заголовок «Регрессия <операция>: <база> → <проверяемая> (+N %)» (несколько
регрессий — через запятую, самая сильная первой; нет регрессий — «Сравнение …: регрессий
нет»), вводная с медианами и p, разделы «Сборки» (версия, номер сборки из ключа `build`,
если есть, время прогона, версия инструмента, схема), «Стенд» (CPU, RAM, ОС, план питания,
масштаб, отпечаток; разные стенды — отдельно и с оговоркой), «Шаги», «Цифры» (таблица по
общим операциям: медиана и MAD, повторы, Δ, p, вердикт `compare_runs` — те же числа, что на
странице сравнения), «Условия прогона» (предупреждения окружения, смешение схем),
«Вложения». Старый JSON без `runs` и `system` переваривается: вердикт «недостаточно
прогонов», стенд прочерками. Тесты — `tests/test_evidence.py` и `tests/test_ui_compare.py`.
