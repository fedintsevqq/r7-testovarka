# Плагины тестов

Свой тест можно добавить без правки ядра: положите файл `plugins/<имя>.py`
рядом с программой (в сборке — рядом с `R7-Testovarka.exe`) и перезапустите
её. Тест появится во вкладке «Производительность» с пометкой «плагин», в
Batch, в наборах `suites/*.toml` и в командной строке (`--op`). Код загрузки —
`r7/plugins.py`, API для плагина — раздел «API для плагинов» в `r7_ops.py`.

## Безопасность

Плагин — обычный код Python. Он выполняется с правами инструмента, а
инструмент обычно запущен от администратора. Значит, плагин может всё:
удалить файлы, поставить программу, отправить данные в сеть.

- Кладите в `plugins/` только файлы из репозитория команды или от человека,
  которому доверяете. Файл из письма или чата сначала прочитайте целиком.
- Список загруженных плагинов пишется в журнал
  `Reports/logs/r7-testovarka.log` при каждом запуске.
- Выключить плагины: `"plugins_enabled": false` в `r7_settings.json` или
  `python -m r7 --no-plugins …`. Для эталонных прогонов и CI это разумное
  умолчание: замер идёт только на коде поставки.

## Контракт

```python
def register(ops):
    """ops — r7_ops.SpreadsheetOps текущего прогона."""
    return [(имя, функция), ...]
```

- **Что берётся.** Только `plugins/*.py`. Файлы на `_`, подпапки и
  `*.py.txt` не загружаются. Каждый файл импортируется отдельно, один раз за
  запуск программы; новый файл виден после перезапуска.
- **register(ops)** только строит функции. Р7 здесь трогать нельзя: его
  зовут и для списка тестов, когда Р7 ещё не запущен, и на каждый прогон —
  чтобы функции были привязаны к `ops` этого прогона.
- **Имя** — непустая строка до 80 символов, без пробелов по краям, не
  совпадает со встроенным тестом и с тестом другого плагина. Имя — ключ в
  отчётах, `selected_tests.json` и наборах: не меняйте его, иначе тренды
  оборвутся.
- **Функция** — без аргументов, с атрибутами:

| Атрибут | Обязателен | Что значит |
|---|---|---|
| `.prepare` | да | Подготовка перед каждым повтором, вне замера: лист, выделение, буфер (правило 3 `CLAUDE.md`) |
| `.cleanup` | нет | Уборка один раз после всех повторов, вне замера. Нужна, если подготовка создала что-то вне истории правок (лист) |
| `.kind` | нет | `"edit"` (по умолчанию) или `"export"`. Экспорт идёт в группе экспорта, по умолчанию на `DEFAULT_FORMAT_TEST_RUNS` повторов |
| `.mutates` | нет | Должна ли операция сдвинуть историю правок. По умолчанию — у правки да, у экспорта нет. Не сдвинула, хотя должна, — прогон считается ошибкой |

Атрибуты проще всего задать через `ops.make_test(fn, prepare, cleanup=None,
kind="edit", mutates=None)`. Связанному методу атрибут не присвоить —
оборачивайте операцию в `def` или `lambda`.

Плохая запись (нет `.prepare`, занятое имя, длинное имя, неверный `.kind`)
пропускается с предупреждением, остальные тесты файла работают. Ошибка
импорта, нет `register`, `register` бросил — пропускается весь файл. Запуск
программы из-за плагина не падает.

## Правила замера

Те же, что у встроенных тестов (`CLAUDE.md`, главные правила 1–8):

1. **В замере одно действие.** Всё остальное — в `.prepare`.
2. **Никакого `time.sleep` внутри операции.** Если Р7 не успевает за
   клавишами — `ops.pace(сек)`: время простоя Р7 вычитается из цифры.
3. **Конец операции определяет инструмент** (пинг редактора, CPU, файл
   экспорта). Ждать результата внутри функции не нужно.
4. **Изменяющий документ шаг — последний**, и через CDP он помечается
   `mutated`. `ops.cdp_call(..., mutates=True)` делает это сам.
5. **Никакого слепого ввода.** Если CDP не сработал, а надёжного пути
   клавишами нет — бросьте исключение. Прогон получит ошибку, а не цифру.
   Клавиши — только `ops.hotkey`/`ops.press`: они проверяют, что спереди
   окно Р7.
6. **Откат делать не нужно.** После каждого повтора общий цикл откатывает
   историю правок (`_restore_history`), как у встроенных тестов.

## API для плагинов

Методы `SpreadsheetOps`, на которые плагин может опираться. Остальные
(с `_` и методы `ops.app`) — внутренности, они меняются без предупреждения.

| Метод | Где звать | Что делает |
|---|---|---|
| `prepare_work_sheet(select_ref=None, require_cdp=True)` | `.prepare` | Рабочий лист фикстуры (самый большой без автофильтра) и выделение. Возвращает `{index, name, rows, cols}`. Не вышло — исключение |
| `select_range(ref)` | `.prepare` | Выделить диапазон `"A1:E1"` на активном листе. Не вышло — исключение |
| `show_sheet(index)` | `.prepare` | Перейти на лист по индексу |
| `cdp_available()` | везде | Есть ли сейчас доступ к api редактора |
| `cdp_call(label, method, *args, mutates=True, check="changed", timeout=None)` | операция | Вызов метода api (`asc_*`). `True` — выполнено или отправлено, запасной путь не нужен. `False` — ничего не произошло, документ не тронут |
| `cdp_script(label, body, check="changed", timeout=None)` | операция | То же для своего тела JS: видны `api`, `win`, `st`; `st.mutated = true` до первой правки; ровно одна строка `r7_webdriver_connector.AFTER_SNAPSHOT_LINE` |
| `hotkey(*keys)`, `press(key, presses=1, pace=0.0)` | операция | Клавиши только в окно Р7 |
| `pace(seconds)` | операция | Пауза внутри замера, вычитается |
| `save_as_format(ext)` | операция | Экспорт через «Сохранить как» (для `kind="export"`) |
| `log(msg)` | везде | Строка в журнал прогона |
| `make_test(fn, prepare, cleanup=None, kind="edit", mutates=None)` | `register` | Ставит атрибуты теста |

`check` в `cdp_call`: `"changed"` — подтвердить сдвигом истории правок;
`None` — не проверять (операция документ не меняет); функция
`(before, after) -> (bool, str)` — своя проверка по снимкам
`{sheets, active, selection, historyIndex, historyPoints, canUndo}`.
Неподтвердившаяся проверка перепроверяется после замера; ответа нет —
прогон помечается `unverified` и в медиану не входит.

## Пример

`docs/plugins/example_bold_column.py` — «Жирный шрифт столбца A». Лежит в
`docs/`, поэтому не загружается. Включить:

```bat
mkdir plugins
copy docs\plugins\example_bold_column.py plugins\
```

Подготовка выбирает рабочий лист и выделяет `A1:A<строк листа>`, в замере
один вызов `asc_setCellBold(true)`. CDP не сработал — исключение: Ctrl+B без
проверенного выделения был бы слепым вводом.

## Отчёт

У результата теста из плагина есть поле `"plugin": "<файл>.py"`. Поле
добавочное, `MEASURE_SCHEMA_VERSION` не меняется, старые читатели его не
замечают. Сравнивать цифры плагина между версиями плагина нельзя так же, как
между схемами замера: изменили операцию — смените и имя теста.

## Юнит-тест плагина

Тест кладите рядом с остальными, в `tests/`, с подменённым коннектором: CDP
прошёл — клавиш нет; CDP не прошёл — нет и слепых клавиш. Шаблон (полная
версия для примера — `tests/test_plugins.py`):

```python
from pathlib import Path

import r7_ops
from r7 import plugins
import r7_Testovarka as r7mod

FOLDER = Path(__file__).resolve().parent.parent / "plugins"


class FakeConnector:
    connected = True

    def __init__(self, result):
        self.result = result

    def sheets_info(self, timeout=None):
        return [{"index": 0, "name": "1", "autofilter": False, "rows": 100, "cols": 5}]

    def show_sheet(self, target, relative=False, timeout=None):
        return {"ok": True}

    def select_range(self, ref, timeout=None):
        return {"ok": True}

    def evaluate(self, js, timeout=None):
        return self.result


def _my_test(bare_r7, result):
    keys = []
    bare_r7._hotkey = bare_r7._press = lambda *k, **kw: keys.append(k)
    bare_r7._op_unverified = None
    bare_r7._webdriver_connector = FakeConnector(result)
    ops = r7_ops.SpreadsheetOps(bare_r7, lambda: 1, print, None)
    tests = plugins.collect_tests(ops, r7mod.R7Testovarka.TEST_DEFINITIONS, folder=FOLDER)
    return dict((t.name, t.fn) for t in tests)["Моё имя"], keys


def test_cdp_ok_no_keys(bare_r7):
    fn, keys = _my_test(bare_r7, {"ok": True, "mutated": True,
                                  "before": {"historyIndex": 1}, "after": {"historyIndex": 2}})
    fn.prepare()
    fn()
    assert keys == []
```

В юнит-тестах папка `plugins/` подменена пустой (`tests/conftest.py`), чтобы
локальные плагины не меняли список тестов; тест плагина передаёт папку сам
(`folder=`). Перед раздачей команде — живой прогон теста на установленном Р7.
