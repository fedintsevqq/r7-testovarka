# План: от 9,5 до «20 из 10» и внедрение в команду

Оценка на 07.10.2026: **9,5**. Планы «до 8» и «до 10» выполнены (кроме шага 5,
ночного прогона по расписанию, который отложен по решению владельца).

Этот план собран из двух источников:

1. Анализ «что отличает инструмент мирового уровня» с трёх сторон: методика
   замера (как у команд производительности Chromium и Mozilla), продукт для
   команды QA вендора офисного пакета, инженерия и эксплуатация.
2. Условия внедрения: инструмент ставится на много разных ПК команды
   тестирования с Windows 10 и 11; позже планируется Linux и macOS.

Второе важнее первого. Инструмент, который точен на одном стенде и не
запускается на половине ПК команды, не стоит ничего. Поэтому этапы идут в
порядке: безопасно и воспроизводимо → работает у всех → команда работает
вместе → методика → инженерия долгой жизни.

Правило прежнее: цифры замера не меняются без новой версии схемы отчёта.
Каждый PR, задевающий прогон, проходит живой набор; описание PR только по
фактическому результату.

## Этап 0. Безопасно и воспроизводимо (неделя)

Делается первым: инструмент работает от администратора, и каждая из этих
проблем на десяти ПК опаснее, чем на одном.

1. **Команда удаления из реестра.** `r7/versions.py:49` читает записи об
   установке и из `HKEY_CURRENT_USER`, куда может писать любая программа без
   прав, а `_build_uninstall_command` возвращает строку как есть, и
   `versions_tab.py:102` запускает её от администратора. Исправление: брать
   команду только из `HKLM`, принимать только `msiexec` с `/X{GUID}`, иначе
   отказ с объяснением. Юнит-тест на подменённую строку.
2. **Удаление папки по жёсткому пути.** `versions_tab.py:118` стирает
   `C:\Program Files\R7-Office` после удаления версии. На стенде Р7 стоит на
   `E:\`: настоящая папка остаётся, а при совпадении пути удалится не то.
   Удалять только `InstallLocation` из той же записи реестра, после проверки,
   что там лежит `DesktopEditors.exe`.
3. **Повторный запуск от администратора** (`r7_Testovarka.py:411`): результат
   UAC не проверяется, аргументы склеиваются без кавычек, в `.exe` `argv[0]`
   уходит повторно. Исправление: `subprocess.list2cmdline`, проверка
   результата `ShellExecuteW`, при отказе остаться в режиме без прав (этап 1).
4. **Ключ `/quiet` для `.exe`-установщика** (`versions_tab.py:142`): у Inno
   Setup и NSIS ключи другие, мастер покажется и будет убит по таймауту как
   «ложный таймаут». Ключ по типу установщика или честное сообщение.
5. **Lock-файл с хэшами.** `requirements.in` → `requirements.lock`
   (`uv pip compile --generate-hashes`), установка в CI и в `build.yml` через
   `--require-hashes`, `pip-audit` шагом CI, Dependabot для pip и actions.
   Обновить Pillow, urllib3, pip (известные уязвимости на 07.10.2026).
6. **Файловый журнал.** `logging` с `RotatingFileHandler` в `Reports/logs/`,
   `add_test_log` дублирует строки туда; `sys.excepthook`,
   `threading.excepthook`, `root.report_callback_exception`,
   `faulthandler.enable`. Без этого сбой у коллеги не разобрать.
7. **Подпись `.exe`, `upx=False`.** Без подписи часть ПК заблокирует запуск
   антивирусом или SmartScreen. Нужен сертификат (Azure Trusted Signing или
   покупной); до его появления хотя бы `upx=False` и контрольная сумма в
   релизе.

Критерий: `pip-audit` чистый, тесты на все четыре исправления, журнал пишется
в файл, `.exe` собирается из lock-файла.

## Этап 3. Методика уровня Perfherder и Chromium perf (две-три недели)

Что уже есть и не предлагается заново: медиана и MAD, прогрев, исключение
`timeout` и `unverified`, Манн-Уитни с порогом 10 %, конец операции по пингу,

1. **Шум стенда из A/A-прогонов и порог под каждый тест.** Режим `--aa` в
   `tests/nightly_local.py` дважды меряет одну версию; из разброса каждого

- Баг x2t DE-8304 и медленный диск стенда: вне кода.

## Как считать

| После этапа | Что получаем |
|---|---|
| 0 | нет известных уязвимостей, сборка воспроизводима, сбой можно разобрать по журналу |
| 1 | инструмент ставится и работает на любом ПК команды без автора рядом |
| 2 | команда видит общие тренды и понимает, какие отчёты сравнимы; регрессия превращается в тикет за минуты |
| 3 | вердиктам верят: порог под тест, поправка, интервал, трасса для разработчика |
| 4 | инструмент живёт годами без автора |
| 5 | все три редактора, реальные файлы клиентов, история всей команды в одном месте |

Объём: этапы 0–2 около четырёх недель, этап 3 ещё две-три, этап 5 по мере
спроса, месяцами. Ночной прогон по
расписанию (шаг 5 плана «до 10») остаётся условием для уведомлений и трендов
по K ночам.
