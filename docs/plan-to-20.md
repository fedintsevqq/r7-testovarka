# План: от 9,5 до «20 из 10» и внедрение в команду

Оценка на 07.10.2026: **9,5**. Планы «до 8» и «до 10» выполнены (кроме шага 5,
ночного прогона по расписанию, который отложен по решению владельца).

Этот план собран из двух источников:

1. Анализ «что отличает инструмент мирового уровня» с трёх сторон: методика
   замера (как у команд производительности Chromium и Mozilla), продукт для
   команды QA вендора офисного пакета, инженерия и эксплуатация.
2. Условия внедрения: инструмент ставится на много разных ПК команды
   тестирования с Windows 10 и 11; позже планируется Linux и macOS.

Второе важнее первого. Инструмент, который точен на одном стенде и не
запускается на половине ПК команды, не стоит ничего. Поэтому этапы идут в
порядке: безопасно и воспроизводимо → работает у всех → команда работает
вместе → методика → инженерия долгой жизни.

Правило прежнее: цифры замера не меняются без новой версии схемы отчёта.
Каждый PR, задевающий прогон, проходит живой набор; описание PR только по
фактическому результату.

## Этап 0. Безопасно и воспроизводимо (неделя)

Делается первым: инструмент работает от администратора, и каждая из этих
проблем на десяти ПК опаснее, чем на одном.

1. **Команда удаления из реестра.** `r7/versions.py:49` читает записи об
   установке и из `HKEY_CURRENT_USER`, куда может писать любая программа без
   прав, а `_build_uninstall_command` возвращает строку как есть, и
   `versions_tab.py:102` запускает её от администратора. Исправление: брать
   команду только из `HKLM`, принимать только `msiexec` с `/X{GUID}`, иначе
   отказ с объяснением. Юнит-тест на подменённую строку.
2. **Удаление папки по жёсткому пути.** `versions_tab.py:118` стирает
   `C:\Program Files\R7-Office` после удаления версии. На стенде Р7 стоит на
   `E:\`: настоящая папка остаётся, а при совпадении пути удалится не то.
   Удалять только `InstallLocation` из той же записи реестра, после проверки,
   что там лежит `DesktopEditors.exe`.
3. **Повторный запуск от администратора** (`r7_Testovarka.py:411`): результат
   UAC не проверяется, аргументы склеиваются без кавычек, в `.exe` `argv[0]`
   уходит повторно. Исправление: `subprocess.list2cmdline`, проверка
   результата `ShellExecuteW`, при отказе остаться в режиме без прав (этап 1).
4. **Ключ `/quiet` для `.exe`-установщика** (`versions_tab.py:142`): у Inno
   Setup и NSIS ключи другие, мастер покажется и будет убит по таймауту как
   «ложный таймаут». Ключ по типу установщика или честное сообщение.
5. **Lock-файл с хэшами.** `requirements.in` → `requirements.lock`
   (`uv pip compile --generate-hashes`), установка в CI и в `build.yml` через
   `--require-hashes`, `pip-audit` шагом CI, Dependabot для pip и actions.
   Обновить Pillow, urllib3, pip (известные уязвимости на 07.10.2026).
6. **Файловый журнал.** `logging` с `RotatingFileHandler` в `Reports/logs/`,
   `add_test_log` дублирует строки туда; `sys.excepthook`,
   `threading.excepthook`, `root.report_callback_exception`,
   `faulthandler.enable`. Без этого сбой у коллеги не разобрать.
7. **Подпись `.exe`, `upx=False`.** Без подписи часть ПК заблокирует запуск
   антивирусом или SmartScreen. Нужен сертификат (Azure Trusted Signing или
   покупной); до его появления хотя бы `upx=False` и контрольная сумма в
   релизе.

Критерий: `pip-audit` чистый, тесты на все четыре исправления, журнал пишется
в файл, `.exe` собирается из lock-файла.

## Этап 1. Работает у всех без автора рядом (неделя)

1. **Мастер первого запуска** на базе `r7/selfcheck.py` и
   `tests/ci_preflight.py`: права, Р7 найден (и где искали), порт CDP
   свободен, фикстура на месте, свободное место, масштаб экрана, исключение
   антивируса для папки Р7. Итог «готово» или список «что исправить» с
   понятными словами. Пробный прогон на файле 10K.
2. **Настройки на машину** (`r7_settings.json` рядом с `.exe`): путь к Р7,
   папка отчётов, повторы по умолчанию, общая папка команды (этап 2). Путь к
   Р7 из настроек имеет приоритет над реестром; жёсткие запасные пути на `C:\`
   остаются последними и пишутся в журнал, когда ими воспользовались.
3. **Режим без прав администратора.** Права нужны только для установки
   версий и сброса файлового кэша. Без них замеры идут, сброс кэша не
   делается, в отчёте метка «кэш ОС не сбрасывался», установка версий
   отключена с объяснением. На корпоративных ПК это обычный случай.
4. **Фикстура в латинице.** Имя `файл-для-теста-Р7-офис-50К.xlsx` хранит «й»
   в NFD; на другом ПК то же имя в NFC не совпадёт с шаблоном
   `batch_config.TEST_FILE_PATTERNS`. Новое имя `r7-test-50k.xlsx`, поиск по
   обоим, генератор создаёт новое. Фикстура едет в составе архива.
5. **Архив «распаковал и запустил»**: `.exe`, фикстура, `README` на одну
   страницу, пустые папки. Собирается в `build.yml` вместе с `.exe`.
6. **Проверка на чистых ПК.** Виртуальные машины с чистыми Windows 10 и 11:
   масштаб 100 % и 150 %, пользователь без прав, Р7 на другом диске, русская
   и английская локаль Windows. Список проверок в `docs/rollout-checklist.md`,
   результаты в PR сборки.
7. **Обновления.** `.exe` проверяет новую версию в GitHub Releases и
   предлагает скачать. Версия инструмента пишется в JSON отчёта (нужно для
   этапа 2).

Критерий: коллега без тебя ставит инструмент по README на одну страницу и
получает первый отчёт.

## Этап 2. Команда работает вместе (две недели)

1. **Метаданные сборки в отчёте**: номер сборки Р7, коммит или ссылка на
   changelog, версия инструмента. Схема отчёта → 10. Без этого регрессию не
   привязать к коду.
2. **Отпечаток машины** в `_capture_environment`: хэш из модели CPU, RAM,
   плана питания, версии ОС, масштаба экрана, диска с папкой данных Р7.
   Сравнение и тренды предупреждают, когда отпечатки разные, как сейчас про
   разные схемы. Калибровка: фиксированная нагрузка на CPU и диск до прогона
   и после, индекс скорости стенда в отчёте. Так «стенд медленный» отделяется
   от «Р7 замедлился».
3. **Общая папка отчётов и единая страница трендов** по всем ПК команды
   (`trends_model` уже умеет много прогонов; добавить фильтр по отпечатку и
   по машине). Постоянные ссылки на сравнения.
4. **Пакет улик для бага**: кнопка на странице сравнения собирает zip из
   двух JSON, HTML-сравнения, окружения, журнала и трассы (этап 3), плюс
   готовый текст тикета: шаги, сборки, цифры, интервал. Сейчас это делается
   вручную, как для `Reports/bugreport_x2t_ods/`.
5. **CLI и наборы тестов как данные**: `python -m r7 run --suite
   suites/smoke.yaml --out Reports/`, набор описывает файл, тесты, повторы и
   бюджеты; выход кодом возврата и JUnit XML. Основа: `r7/nightly.py` и
   `selected_tests.json`.
6. **Бюджеты и экран «релиз готов / не готов»**: абсолютные пороги в наборе
   («открытие 50K ≤ 10 с»), одна страница с причинами для менеджера.
7. **Сценарии в интерфейсе**: soak, многодокументный и восстановление после
   падения уже написаны в `r7/scenarios.py`, но из окна не запускаются.
   Вкладка «Сценарии».
8. **Уведомления** в Telegram или Slack с вердиктом и ссылкой на отчёт
   (`r7/notify.py`, вебхук в настройках). Полезны только вместе с ночным
   прогоном по расписанию (шаг 5 плана «до 10»), который отложен.

Критерий: два человека на двух ПК получают отчёты, видят их на одной
странице трендов и понимают, можно ли сравнивать.

## Этап 3. Методика уровня Perfherder и Chromium perf (две-три недели)

Что уже есть и не предлагается заново: медиана и MAD, прогрев, исключение
`timeout` и `unverified`, Манн-Уитни с порогом 10 %, конец операции по пингу,
подготовка вне замера, `_pace`, снимок окружения, сброс кэша, детектор
утечек, версия схемы, эталон в `Reports/baseline/`.

1. **Шум стенда из A/A-прогонов и порог под каждый тест.** Режим `--aa` в
   `tests/nightly_local.py` дважды меряет одну версию; из разброса каждого
   теста собирается `Reports/noise_profile.json`, привязанный к отпечатку
   машины. В `compare_runs` порог = `max(k × CV, пол)`. Сейчас у Ctrl+V
   разброс 0,1 % от медианы, у открытия 2,9 %: единый порог 10 % для первого
   слеп, для второго близок к шуму.
2. **Поправка на 17 сравнений** (Холм или Бенджамини-Хохберг) в
   `nightly.compare_reports` и `comparison_model`; в отчёте скорректированное
   p. На десяти машинах ложных тревог без поправки будет в десять раз больше.
3. **Доверительный интервал вместо голого p.** Сдвиг Ходжеса-Лемана и
   bootstrap-интервал отношения медиан на чистом Python; при n ≤ 8 точный
   перестановочный p. Вердикт по интервалу: регрессия, эквивалентно, не
   определено. В отчёте «+12 % [+7; +18]». «Без изменений» перестаёт значить
   «не хватило повторов».
4. **Тренд против медианы последних K прогонов** и точка смены на ряде
   (CUSUM или E-divisive); на графике отметка, с какой сборки начался сдвиг.
   Сейчас `nightly.previous_report` берёт один предыдущий, который сам мог
   быть шумным.
5. **Сэндвич A-B-A в Batch**: базовая версия повторяется в конце; расхождение
   A1 и A2 больше шума помечает весь Batch.
6. **Управление стендом**: на время прогона план питания «Высокая
   производительность» с возвратом прежнего (как `_suspend_autosave`), частота
   CPU в `ResourceSampler` с пометкой троттлинга у повтора. Приоритет и
   привязку процессов Р7 к ядрам не трогать: это меняет объект замера.
7. **Сколько нужно повторов**: по CV из п. 1 считать, какой эффект ловят 7
   повторов, и писать это в отчёт; добирать повторы, пока интервал шире цели.
8. **Трасса при регрессии**: отдельный диагностический повтор вне замера с
   `Tracing.start` и `Profiler.start`, файл для Perfetto и `.cpuprofile`
   рядом с отчётом, разбивка по фазам. Сначала проверить на живом Р7, отдаёт
   ли CEF `Tracing` на page-таргете.
9. **Что видит пользователь** (схема → 11): время до первого кадра после
   операции (двойной `requestAnimationFrame`), самая длинная блокировка
   интерфейса (`longtask`), пик JS-кучи.
10. **Бисект по сборкам**: двоичный поиск между двумя дистрибутивами одной
    операцией, вердикт по п. 3. Ценен, когда сборок много.

Критерий: вердикт сравнения содержит интервал, порог теста и поправку;
A/A-прогон даёт «без изменений» по всем 17 тестам.

## Этап 5. За пределами: от 15 к 20 (месяцы, по мере спроса)

Этапы 0–4 делают инструмент точным, надёжным и удобным для команды
тестирования таблиц. Дальше растёт охват, и каждый пункт здесь большой.

1. **Документы и презентации.** `DocumentOps` и `PresentationOps` поверх тех
   же `asc_*` api: открытие, вставка 100 страниц, смена стиля, экспорт DOCX,
   PDF, PPTX. Готовность, откат и подтверждение `mutated` для каждого
   редактора пишутся заново. Самая большая ценность для вендора.
2. **Корпус реальных файлов.** Папка `Corpus/` с обезличенными файлами
   клиентов, прогон «открытие, пересчёт, экспорт» по каждому и матрица
   «файл × версия». Регрессии на «боевых» документах, а не на одной фикстуре.
3. **Плагины тестов.** Регистрация операций через `plugins/*.py` по контракту
   `SpreadsheetOps.tests()`: имя, функция, `.prepare`, юнит-тест. Новый тест
   без правки ядра.
4. **История на сервере.** Небольшой сервис принимает JSON отчётов со всех
   ПК, хранит историю, строит тренды и сравнения по ссылке, отвечает на
   вопрос «когда это сломалось» за секунды. Замена общей папке из этапа 2,
   когда машин станет больше пяти.
5. **Linux и macOS.** Порт четырёх модулей из раздела ниже, свой набор значков,
   сборка в CI на трёх ОС. Делается после того, как Р7 на этих ОС станет
   целью команды.
6. **Интеграция с трекером и CI вендора.** Тикет из пакета улик создаётся
   автоматически, прогон запускается на каждую ночную сборку Р7, результат
   приходит в тот же PR или канал сборки.

## Что не входит

- Совместное редактирование: нужен сервер документов, это другой продукт.
- Английский интерфейс: команде вендора почти не нужен.
- Запись сценариев с клавиатуры: противоречит правилу «никакого слепого
  ввода».
- Баг x2t DE-8304 и медленный диск стенда: вне кода.

## Как считать

| После этапа | Что получаем |
|---|---|
| 0 | нет известных уязвимостей, сборка воспроизводима, сбой можно разобрать по журналу |
| 1 | инструмент ставится и работает на любом ПК команды без автора рядом |
| 2 | команда видит общие тренды и понимает, какие отчёты сравнимы; регрессия превращается в тикет за минуты |
| 3 | вердиктам верят: порог под тест, поправка, интервал, трасса для разработчика |
| 4 | инструмент живёт годами без автора |
| 5 | все три редактора, реальные файлы клиентов, история всей команды в одном месте |

Объём: этапы 0–2 около четырёх недель, этап 3 ещё две-три, этап 5 по мере
спроса, месяцами. Ночной прогон по
расписанию (шаг 5 плана «до 10») остаётся условием для уведомлений и трендов
по K ночам.
