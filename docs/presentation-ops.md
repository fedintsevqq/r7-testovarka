# Презентации (.pptx): операции, готовность, откат

Этап 5, пункт 1 плана «до 20», часть «презентации» (07.10.2026). Устроено
как документы (`docs/document-ops.md`): тот же воркер, та же общая часть
нетабличных редакторов, свои JS, фикстура и операции.

## Что меряется

Набор `suites/slides.toml` (`[suite] editor = "presentation"`), запуск:

```bash
.venv/Scripts/python.exe -m r7 run --suite suites/slides.toml --gate
```

| Тест | Что делает в замере | Подтверждение |
|---|---|---|
| Повторное открытие файла | холодный запуск Р7 с презентацией | готовность + число слайдов устоялось |
| Добавление 50 слайдов | 50 × `AddSlide()` одним вызовом JS, текущий — первый слайд | история сдвинулась, слайдов ровно +50 |
| Дублирование всех слайдов | `SelectAllSlides()`, затем `DublicateSlide()` (так в api) | история сдвинулась, слайдов вдвое больше |
| Смена темы | `ChangeTheme(i)` — тема редактора с другим именем | история сдвинулась, имя темы мастера другое |
| Переход ко всем слайдам | `SelectAllSlides()`, затем `ApplySlideTransition` с «Выцветанием» (Fade), 0,7 с | история сдвинулась, переход у каждого слайда |
| Сохранение в PDF (презентация, x2t) | общий «Сохранить как», тип `(*.pdf)` | файл — `%PDF-` |
| Сохранение в PPTX (презентация, x2t) | то же, тип `(*.pptx)` | в `[Content_Types].xml` — `presentationml.presentation.main` |

Имена — `r7_pptx_ops.PRESENTATION_TEST_DEFINITIONS`, повторы по умолчанию —
`DEFAULT_PPTX_RUNS` (правки 5, экспорт 3). Проверка формата знает и ODP
(`mimetype` `opendocument.presentation`), в набор он не входит.

Тема выбирается так: кандидаты `THEME_CANDIDATES = (1, 2, 3, 4, 0)` —
индексы в `api.ThemeLoader.Themes.EditorThemes`. Берётся первый, который
есть в списке и чьё имя (`Name`, `name` или `get_Name()`) не совпадает с
темой мастера. Список не читается — первый кандидат. Тема фикстуры
называется «R7 Testovarka», со встроенными она не совпадает.

## Фикстура

`r7/pptx_fixtures.py`, только стандартная библиотека. `generate_pptx(path,
slides=50, seed=42)` пишет 16:9: мастер с заголовком и текстом, два макета
(«Титульный слайд», «Заголовок и объект»), тема «R7 Testovarka». Слайд 1 —
титульный, каждый пятый — заголовок и таблица 6 × 4, остальные — заголовок,
список из 4–6 пунктов и две фигуры (прямоугольник, эллипс, стрелка…).
Обязательные части пакета: `presentation.xml`, `presProps`, `viewProps`,
`tableStyles`, мастер и макеты со связями, тема, слайды со связями,
`[Content_Types].xml`, `docProps/core.xml` и `app.xml`. Тесты проверяют, что
каждая связь ведёт в существующую часть и у каждой части есть тип
содержимого. Один seed — побайтно один файл. Каноническое имя —
`TestFiles/r7-test-slides-50.pptx`; нет файла — воркер создаёт его сам.

## Как устроен прогон

`_presentation_worker` ставит `_run_editor = "presentation"` и зовёт
`_spreadsheet_worker`. В `R7Testovarka` первыми стоят
`PresentationRunMixin` (`r7/pptx_run.py`), затем `DocumentRunMixin`
(`r7/doc_run.py`).

Общая часть нетабличных редакторов живёт в `DocumentRunMixin` и берёт JS из
профиля редактора (`EditorProfile`, `_editor_profile()`): готовность с
досчётом, конец операции по пингу, снимок и откат истории `Undo`,
отложенная проверка, автосохранение, диагностика api, ключ `editor` в
отчёте. `PresentationRunMixin` подменяет только своё:

| Метод | Презентация |
|---|---|
| `_editor_profile` | `PRESENTATION_PROFILE`: JS из `r7/pptx_js.py` |
| `_locate_test_file` | фикстура презентации, нет — генерация |
| `_make_run_ops` | `r7_pptx_ops.PresentationOps` |
| `_bold_ready_probe` | кнопка «Добавить слайд» вместо «Жирного» (ниже) |
| `editor_test_names` | + `"presentation"` |

JS — `r7/pptx_js.py`. Пролог `PPTX_API_PRELUDE`: api — `editor` (или
`Asc.editor`, или `PE.getController('Main').api`) с `getCountPages` и
`WordControl.m_oLogicDocument.Slides`. У редактора документов тоже есть
`WordControl` и `getCountPages`, поэтому пролог документа теперь отвергает
api с `Slides`, а пролог презентации — api без него. Снимок (`docState`):
`pages` (`getCountPages`), `slides`, `historyIndex`, `historyPoints`,
`canUndo`, `recalcBusy` (всегда `null`), `theme` (имя темы первого мастера),
`transitions` (слайдов с `timing.TransitionType > 0`; не читается — `null`).
Операции собираются тем же `_op_js`, `mutated` ставится прямо перед
изменяющим вызовом, он последний (правило 7). Выделение всех слайдов
презентацию не меняет.

## Готовность и конец операции

**Маркер.** Кнопка «Жирный» в редакторе презентаций доступна, только когда
курсор в тексте. После открытия выделен слайд, а не текст, поэтому она так
и осталась бы недоступной, а общий детектор, видя найденную, но выключенную
кнопку, не переходит на CPU-путь и дождался бы таймаута. Для презентации
проба та же (`_BOLD_READY_PROBE_JS`: `MutationObserver` и отметка времени
включения), но по кнопке «Добавить слайд»: `#id-toolbar-button-add-slide`,
`button[id*="add-slide"]`, `button[id*="addslide"]`. Только `<button>` и
точный id: у слотов разметки класса `disabled` не бывает, и такой узел дал
бы готовность раньше времени. Кнопка не найдена — `{found: false}`,
готовность идёт по CPU, как без CDP. Маркер в отчёте называется так же
(`bold`, `bold+layout`) — это имя пути детектора, а не кнопки.

**Досчёт.** Признака идущего пересчёта у презентации не найдено
(`recalcBusy = null`), поэтому `_doc_layout_settle` считает готовым, когда
число слайдов не меняется `DOC_LAYOUT_STABLE_POLLS` (2) опроса подряд с
шагом 0,15 с. Если число уже было итоговым на первом чтении, момент
готовности не сдвигается.

**Конец правки** — тишина пинга редактора (`_wait_renderer_idle`), как у
таблиц. Число слайдов после всех четырёх правок меняется синхронно внутри
вызова, так что дополнительного ожидания обычно нет. Миниатюры слайдов
рисуются по таймеру — их работа держит рендерер занятым, пинг её видит.

## Откат и подтверждение

Перед каждым повтором (`_editor_prepare`, вне замера): число слайдов
устоялось, выделение объектов снято, текущий — первый слайд
(`WordControl.GoToPage(0)`). После повтора — `Undo` до `History.Index`
снимка (не больше `DOC_UNDO_MAX_STEPS` = 400 шагов; «Добавление 50
слайдов» — 50 точек), затем снова устоявшееся число слайдов и простой Р7.

Проверка сразу по снимку `after` из ответа JS; не подтвердилась — ещё раз
после конца замера (`_flush_pending_cdp_verify`). Не подтвердилось и
тогда — повтор `unverified`, в медиану не входит. Это важно для «Смены
темы»: если `ChangeTheme` догружает файл темы асинхронно, тема может
примениться после тишины пинга — тогда проверка сразу не пройдёт, а
после замера пройдёт, и цифра повтора будет занижена (см. живые проверки).

## Без CDP

Клавиатурного запасного пути у правок нет: полсотни нажатий в замере,
слепая работа с панелями тем и переходов (правило 8). Нет CDP или api не
выполнил операцию, не тронув презентацию, — тест падает с ошибкой «нет CDP
или api презентации не выполнил операцию». Экспорт идёт общим
`_save_as_format`.

## Отчёт

`performance_full_*.json`: `"editor": "presentation"` (ключ необязательный,
схема та же — правило 11). В HTML в блоке «Стенд» — «Редактор: презентации
(.pptx)», в трендах — отдельные линии (`… · презентации (.pptx)`). CLI
отказывается сравнивать набор презентации с эталоном другого редактора
(код 3).

Метрики интерфейса, трасса регрессий и Batch работают как у документов
(`docs/document-ops.md`, «Метрики интерфейса, трасса и Batch»): взвод и
сбор метрик — прологом `PPTX_API_PRELUDE`, `trace --op "Смена темы"` сам
находит редактор, в диалоге Batch — «Презентация (.pptx)» с фикстурой
`r7-test-slides-50.pptx`.

## Живая проверка

Координатор 07.10.2026 проверил на Р7 2026.3.2 (`--new:slide`) api
`editor` во фрейме глубины 1 с `WordControl`, `Slides.length`,
`History.Index`, `asc_getCanUndo` и наличие `AddSlide`, `DublicateSlide`,
`SelectAllSlides`, `ChangeTheme`, `ApplySlideTransition`, `Undo`.

08.10.2026 весь набор `suites/slides.toml` прошёл на том же Р7: «Релиз
готов», 7 из 7 операций, ни одного `unverified` и `timeout`, 2 мин. Что
это подтвердило:

1. Р7 открывает сгенерированную `r7-test-slides-50.pptx`: 50 слайдов,
   тема «R7 Testovarka», в редакторе 11 тем.
2. Маркер «Добавить слайд» работает: готовность наступает по нему.
3. 50 вызовов `AddSlide()` дают ровно +50, `DublicateSlide` после
   `SelectAllSlides` — ровно вдвое больше (50 → 100).
4. `ChangeTheme` меняет тему на «Basic», но не синхронно: в первом повторе
   снимок сразу после вызова показывает старое имя, проверка после замера
   проходит. В остальных повторах тема видна сразу.
5. `ApplySlideTransition` ставит переход всем 50 слайдам.
6. Подготовка (`GoToPage(0)`, `RemoveSelection`) точку истории не
   создаёт: перед каждой правкой индекс истории −1.
7. Откат 50 точек `Undo` одним вызовом — около 0,4 с, тема и переходы
   откатываются тоже.
8. «Сохранить как» открывается через вкладку «Файл», типы `(*.pdf)` и
   `(*.pptx)` выбираются, x2t отдаёт файл с кодом 0.

Одно замечание к набору. «Переход ко всем слайдам» занимает 7 мс: это
запись свойства без перерисовки. Порог в 2 % от 7 мс меньше точности
пинга (~1 мс), так что регрессию эта операция поймает, только если она
станет в разы медленнее.

Скрипт для ручной проверки — `tests/manual_slides_smoke.py` (правки,
снимки, откат, маркер готовности, без экспорта); полный прогон —
`python -m r7 run --suite suites/slides.toml`.
