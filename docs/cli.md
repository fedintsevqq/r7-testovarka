# Командная строка: `python -m r7`

Прогон без окна — для CI, Планировщика заданий и коллег, которым нужен
ответ «можно ли выпускать», а не интерфейс. Тот же воркер, что у вкладки
«Производительность» (`_spreadsheet_worker`), те же отчёты в `Reports/`,
плюс набор тестов в TOML, бюджеты, сравнение с эталоном, JUnit XML и
страница «Релиз готов / Не готов». Код — `r7/cli.py`, `r7/suites.py`,
`r7/gate.py`; шаблон страницы — `templates/html/gate.html`.

Р7-Офис должен быть закрыт, клавиатуру и мышь во время прогона не трогать:
инструмент сам запускает редактор и шлёт ему клавиши. Запускать из сессии
пользователя (не службой), как и ночной прогон.

## Команды

```bat
.venv\Scripts\python.exe -m r7 check
.venv\Scripts\python.exe -m r7 suites
.venv\Scripts\python.exe -m r7 run --suite suites\smoke.toml --gate --junit Reports\junit.xml
.venv\Scripts\python.exe -m r7 run --suite suites\release.toml --baseline Reports\baseline\performance_full_20261007_120000.json --gate --junit Reports\junit.xml --out D:\perf
```

| Команда | Что делает |
|---|---|
| `check` | Проверки стенда из мастера первого запуска (`r7/firstrun.py`) без окна: сборка, права, Р7 найден и закрыт, порт CDP, фикстура, диск, масштаб, пакеты. Код 1, если есть ✗. |
| `suites [--dir папка]` | Список наборов `suites/*.toml` с проверкой имён и повторов; битый набор помечен ✗ и даёт код 3. |
| `run --suite файл [--out папка] [--baseline json] [--junit файл] [--gate]` | Прогон набора, отчёты как у вкладки (`performance_full_<ts>.json`, HTML, Excel), таблица итогов в консоль, при `--junit` — JUnit XML, при `--gate` — `gate_<ts>.html` рядом с отчётом. |

`--out` переопределяет папку отчётов (`Reports/` или `reports_folder` из
`r7_settings.json`). `--baseline` — любой `performance_full_*.json`,
например из `Reports/baseline/` или прошлого ночного прогона.

Журнал прогона идёт в консоль с меткой времени и в
`Reports/logs/r7-testovarka.log` (`r7/logfile.py`). Ctrl+C останавливает
после текущей операции, Р7 закрывается штатно, отчёт по сделанному
сохраняется, код выхода — 2.

## Коды выхода

| Код | Значение |
|---|---|
| 0 | Все операции набора в норме: бюджеты не превышены, регрессий к эталону нет. |
| 1 | Хотя бы одна операция выше бюджета, с регрессией, с ошибкой или не измерена (`run`); есть ✗ (`check`). |
| 2 | Прогон не удался: отчёта нет, воркер упал, прерван Ctrl+C. |
| 3 | Условия не выполнены: Р7 запущен или не найден, нет фикстуры 50К, набор или эталон не читаются. |

## Формат набора

```toml
[suite]
name = "smoke"
description = "Открытие и три ключевые операции, ~5 минут"

[tests]                               # имя — точно как в TEST_DEFINITIONS
"Повторное открытие файла" = 3        # повторов, 1..20 (RUNS_MIN..RUNS_MAX)
"Выделение всех ячеек (Ctrl+A)" = 5

[budgets]                             # необязательно: потолок медианы, секунд
"Повторное открытие файла" = 12.0

[compare]                             # необязательно
min_effect_pct = 10                   # порог практической значимости compare_runs
```

- Имя теста с опечаткой — ошибка со списком допустимых имён. Повторы вне
  1..20 обрезаются, как в поле «×N»; не целое — ошибка.
- Бюджет можно задать только тесту из `[tests]`; значение — число больше нуля.
- Неизвестный раздел (`[test]` вместо `[tests]`) — ошибка, а не молчаливый пропуск.
- `suite_to_selection(suite, TEST_DEFINITIONS)` даёт структуру
  `selected_tests.json` — интерфейс сможет загрузить набор как выбор тестов.

Поставляемые наборы: `smoke.toml` (открытие ×3, Ctrl+A, Ctrl+V, ВПР ×5),
`release.toml` (все 17 тестов с повторами по умолчанию и двумя бюджетами
с запасом), `export.toml` (четыре экспорта ×3). ODS на фикстуре 50К роняет
x2t (DE-8304) — в `release` и `export` он даст «ошибка» и «Не готов».

## Вердикт и страница готовности

`r7/gate.py` считает по каждому тесту набора:

| Вердикт | Когда |
|---|---|
| в норме | медиана не выше бюджета, регрессии к эталону нет |
| выше бюджета | медиана больше `[budgets]` |
| регрессия | `compare_runs` (Манн-Уитни, p < 0,05, сдвиг больше `min_effect_pct`) по действительным повторам — тем же, что вошли в медиану |
| ошибка | ни одного действительного повтора (`error` в записи) |
| не измерено | операция из набора в отчёт не попала (прогон прерван) |

«Релиз готов» — все в норме; любая причина против — «Не готов». Меньше
пяти повторов на любой стороне — вердикта сравнения нет, показана только
Δ %. Эталон другой схемы замера или той же версии Р7 — предупреждение на
странице. Открытие в наборе называется «Повторное открытие файла», а в
отчёте — «Открытие файла» (`gate.result_name`).

Страница `gate_<ts>.html`: один крупный блок вердикта с причинами, таблица
(медиана ± MAD, n, бюджет, эталон, Δ, вердикт, причина), «Как считалось».
Оформление — `base.html`: токены цвета, светлая и тёмная темы, печать в PDF.

## JUnit для CI

`--junit` пишет один `<testsuite>` с `<testcase>` на каждый из 17 тестов:
`failure` — выше бюджета или регрессия, `error` — ошибка или не измерено,
`skipped` — тест в набор не входит. Любой CI (GitHub Actions, GitLab,
Jenkins) покажет его как результаты тестов. Пример шага на self-hosted
раннере с меткой `r7-installed`:

```yaml
- run: .venv\Scripts\python.exe -m r7 run --suite suites\smoke.toml --gate --junit Reports\junit.xml
- uses: actions/upload-artifact@v4
  if: always()
  with: { name: perf, path: Reports/ }
```

Код выхода 1 завершит шаг с ошибкой, как и ожидает CI; 2 и 3 — тоже, но
по причинам стенда, а не Р7 — смотрите журнал.

## Как устроен прогон без окна

`cli.make_headless_app` собирает `R7Testovarka` через `__new__` и
`_init_state()` (состояние прогона и папки — всё, что в `__init__` не Tk),
подменяет `add_test_log`, `_ui_call`, `_set_perf_progress` и
`_show_post_test_dialog` заглушками и читает версию Р7 из реестра
(`_read_current_version_from_registry`, безопасна вне главного потока).
`r7_Testovarka` импортируется лениво только в `r7/cli.py`: при
`python -m r7` он не `__main__`, второй копии класса нет. Воркер идёт в
фоновом потоке, главный ждёт его короткими `join`, чтобы ловить Ctrl+C и
ставить `stop_event`.
