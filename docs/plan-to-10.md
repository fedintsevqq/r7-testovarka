# План: от 8 до 10

План «до 8» (`docs/plan-to-8.md`) выполнен 07.10.2026: операции в одном модуле, пакет
`r7/` вместо файла на 13 000 строк, отчёты на шаблонах, интерфейс без логики, ночной
контур. Что отделяет инструмент от «10» — по замерам на 07.10.2026.

| Мера | Сейчас | Цель |
|---|---|---|
| Покрытие юнит-тестами (без живого Р7) | 68 % (прогон Batch 24 %, окна сравнения/версий 4–19 %) | ≥ 85 % всего, ≥ 90 % без `r7/ui/` |
| Самые длинные функции | прогон Batch ~220 строк, окно хэшей 340, генератор файла 266, `_wait_until_r7_ready` 384 | ≤ 150, логика — в чистых функциях |
| Модули больше 800 строк | 5 (`cdp`, `export`, `readiness`, `dialogs`, `measure`) | 0 |
| Живой набор | 1 нестабильный провал из 4 запусков | 20 запусков подряд без провала |
| Сборка .exe | спецификация PyInstaller вне репозитория, сборка вручную | спецификация в git, CI собирает и проверяет запуск |
| Руководство пользователя | нет (есть CLAUDE.md для разработчика) | README: установка, запуск, как читать отчёты |

## Шаг 1. Прогон Batch — фазы и дым-тест (как у вкладки, #61)

`_batch_run_single_version` и `_batch_worker`: открытие, замеры, итоги, отчёт, закрытие —
методами; дым-тест всего Batch с подменёнными границами (установка, Р7, замеры): порядок
версий, остановка, пауза, ошибка установки, «остановиться при первой ошибке», Р7
закрывается при любом исходе. Общий код открытия файла вкладки и Batch — один метод.

## Шаг 2. Нестабильный живой набор

Поймать мигающий тест (20 запусков, журнал с `-rf`), найти причину, починить в
инструменте. Критерий — 20 запусков подряд без провала.

## Шаг 3. Длинные функции и большие модули

- Окно хэшей и генератор файла: расчёт и сравнение хэшей, проверка параметров
  генератора — чистые функции с тестами, окно только рисует.
- `_wait_until_r7_ready` (384 строки): маркеры готовности (кнопка «Жирный», CPU,
  модалки) — отдельные шаги.
- Модули больше 800 строк делятся по швам: `export` (диалог «Сохранить как» / CSV и
  x2t), `readiness` (кнопка «Жирный» / ожидание), `dialogs` (закрытие / контекстное
  меню), `cdp` (шаги api / подготовки тестов), `measure` (цикл / детекторы).
- Пороги `OP_*`, `READY_*`, `CDP_*` — к примесям, которые их читают, а не в классе
  приложения.

## Шаг 4. Покрытие — порог в CI

`coverage` уже стоит в CI; добавить `--fail-under` (сначала по факту, затем 85 %) и
отчёт по модулям в сводке запуска. Непокрытые ветки окон — тестами на настоящем Tk
(как `tests/test_batch_start.py`).

## Шаг 5. Сборка .exe в CI

`R7-Testovarka.spec` — в репозиторий (с `templates/html`), job `build` на
`windows-latest`: PyInstaller, запуск `R7-Testovarka.exe --self-check` (импорт всех
модулей, шаблоны отчётов на месте, рендер пустого отчёта), артефакт.

## Шаг 6. Руководство пользователя

`README.md`: что меряет инструмент и чем отличается от секундомера; установка
(`.venv`, права администратора, версия Р7); запуск вкладки, Batch, своего файла;
как читать отчёты (медиана ± MAD, метки «таймаут», «без подтверждения», «диск»,
«Условия прогона»); сравнение версий и тренды; ночной контур; известные ограничения.

## Шаг 7. Тихие ошибки

Аудит `except Exception: pass` по пакету: каждая — либо с причиной в комментарии
(«окно уже закрыто»), либо с записью в журнал. Тест-страж на новые голые глушилки.
