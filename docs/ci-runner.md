# Раннер для живого прогона (perf.yml)

`perf.yml` гоняет живые проверки на настоящем Р7-Офис: CDP-операции
(`tests/manual_cdp_smoke.py`) и набор `tests/live` (открытие, операции,
экспорт в 4 формата, аварийное закрытие). GitHub-hosted раннеры для этого не
годятся: Р7 нужно поставить, а инструмент жмёт клавиши и читает окна.

Шаги workflow проверены 06.10.2026 на стенде, вручную, по одному, в чистой
копии репозитория и новом окружении `.venv-ci` (Python 3.12 из PATH):
окружение, предусловия, фикстура, CDP-smoke, 7 живых тестов, закрытие Р7 — всё
прошло. Сам GitHub-раннер на стенде не регистрировался.

## Версия раннера

Действия в workflow обновлены до версий на Node.js 24: `actions/checkout` v7,
`actions/setup-python` v7, `actions/upload-artifact` v7. Им нужен GitHub
Actions Runner не ниже 2.327.1. Будущий раннер `r7-installed` ставим на этой
версии или новее, а уже зарегистрированный обновляем до запуска workflow.

## Машина

- Windows 10/11 с установленным Р7-Офис. Если версий две, текущей считается
  первая запись в реестре — и версия в отчёте, и запускаемый exe берутся из
  неё (`_find_r7_path`). Надёжнее держать одну.
- Python 3.11+ в PATH, либо путь к нужному в переменной репозитория
  `R7_CI_PYTHON` (Settings → Secrets and variables → Actions → Variables).
  Окружение `.venv-ci` workflow создаёт сам.
- Машина выделенная: шаг «Закрыть Р7 при любом исходе» завершает **все**
  процессы Р7 на ней.

## Регистрация раннера

1. Settings → Actions → Runners → New self-hosted runner → Windows, выполнить
   показанные команды в папке вроде `C:\actions-runner`.
2. На вопрос о метках добавить `r7-installed` (метки `self-hosted` и `windows`
   ставятся сами).
3. **Не устанавливать как службу** (на вопрос «Run as service?» ответить N).
   Служба работает в сессии 0 без рабочего стола: pyautogui и UI Automation
   там не работают, а `tests/ci_preflight.py` откажется запускаться с причиной
   «процесс в сессии 0».
4. Запускать `run.cmd` в сессии пользователя. Чтобы он поднимался после
   перезагрузки — автовход этого пользователя и ярлык `run.cmd` в
   автозагрузке (`shell:startup`).

## Сессия

- Экран не должен блокироваться и засыпать на время ночного прогона (план
  электропитания: «Отключать дисплей» и «Сон» — никогда, без заставки с
  паролем). На заблокированном экране окна не получают фокус, и защита
  `_ensure_r7_foreground` остановит тест «на переднем плане не Р7».
- Р7-Офис перед прогоном закрыт: иначе CDP-порт занят, а предусловия
  откажутся запускаться.
- Права администратора не обязательны для `perf.yml` (сброс файлового кэша
  ОС для холодного старта без них просто пропускается с предупреждением).

## Запуск

Actions → perf-smoke → Run workflow, либо по расписанию в 02:00 UTC.
Одновременно идёт только один прогон (`concurrency: perf-r7`). Отчёты из
`Reports/` выгружаются артефактом при любом исходе и хранятся 14 дней.

Проверить стенд без GitHub:

```bash
.venv/Scripts/python.exe tests/ci_preflight.py
```
