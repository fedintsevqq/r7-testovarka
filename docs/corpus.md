# Корпус реальных файлов

План «до 20», этап 5, пункт 2. Одна фикстура на 50 000 строк ловит не всё:
у клиентов сводные таблицы, тысячи формул, условное форматирование, старые
`.xls`. Корпус — папка таких файлов. По каждому инструмент меряет открытие,
полный пересчёт и экспорт, а сравнение двух прогонов показывает матрицу
«файл × версия»: где новая сборка Р7 стала медленнее на «боевом» документе.

## Папка и правила

`Corpus/` рядом с программой (или `--dir`). Файлы `.xlsx`, `.xls`, `.ods`,
`.csv`, можно в подпапках. Пропускаются файлы блокировки (`~$книга.xlsx`,
`.~lock.книга.xlsx#`), скрытые папки и дубли по содержимому.

Файлы клиентов в репозиторий не попадают: `/Corpus/*` в `.gitignore`, в git
лежат только `Corpus/README.md` (правила обезличивания) и
`Corpus/corpus.example.toml`. Коротко:

- только обезличенные файлы: ФИО, телефоны, почта, паспорта, ИНН, счета
  заменены похожими значениями, формулы и объём на месте;
- свойства документа, комментарии, скрытые листы и имена тоже проверены;
- файлы — только для команды, инструмент их никуда не отправляет;
- отчёт наружу — с `--hide-names`.

Р7 открывает **копию** файла во временной папке (`%TEMP%\testovarka_corpus_*`), а не
исходник. Lock-файлы и автосохранение остаются в копии, исходник не
перезаписать даже по ошибке. Копия удаляется после файла.

## Запуск

```bat
.venv\Scripts\python.exe -m r7 corpus
.venv\Scripts\python.exe -m r7 corpus --steps open,export --formats pdf,xlsx --open-runs 5
.venv\Scripts\python.exe -m r7 corpus --dir D:\corpus --hide-names --out D:\perf
.venv\Scripts\python.exe -m r7 corpus-compare Reports\corpus_20261007_120000.json Reports\corpus_20261009_120000.json
```

Р7 должен быть закрыт и найден (`python -m r7 check`). Рабочая фикстура
корпусу не нужна. Права администратора не обязательны, но без них не
сбрасывается файловый кэш ОС, и открытие меряется «тёплым» (как у вкладки,
`docs/first-run.md`).

| Аргумент | По умолчанию | Что значит |
|---|---|---|
| `--dir` | `Corpus/` | папка корпуса |
| `--steps` | `open,recalc,export` | шаги; порядок всегда открытие → пересчёт → экспорт |
| `--formats` | `pdf` | форматы экспорта: `pdf`, `ods`, `csv`, `xltx`, `xlsx` |
| `--open-runs` / `--recalc-runs` / `--export-runs` | 3 / 5 / 3 | повторы шагов, 1..20 |
| `--hide-names` | выкл. | в JSON и HTML вместо имён — id файла |
| `--out` | `Reports/` | папка отчётов |

Ctrl+C останавливает после текущего замера: Р7 закрывается штатно, отчёт по
пройденным файлам сохраняется, код выхода 2.

## Что меряется

На каждый файл — одна сессия Р7, как у вкладки «Производительность»
(`r7/corpus_runner.py`):

1. **Открытие.** Те же `_extra_opens` и `_launch_r7`: холодный старт
   (очистка временных объектов Р7, сброс файлового кэша ОС при правах
   администратора, удаление старых lock-файлов), готовность
   `_wait_until_r7_ready`, запись `_open_result`. Повторы — независимые
   холодные старты, первый не отбрасывается. Последний запуск остаётся
   открытым для следующих шагов. Ожидание загрузки — `open_timeout_sec`
   (120 с, в манифесте до 1800). Не загрузился — открытие записано как
   таймаут, пересчёт и экспорт не меряются, у файла ошибка.
2. **Пересчёт.** `asc_calculate(Asc.c_oAscCalculateType.All)` через CDP,
   цикл повторов `_measure_op_repeated`: подготовка и ожидание простоя вне
   замера, конец — пинг редактора. Живая проба на Р7 2026.3.2 (07.10.2026):
   у api есть `asc_calculate`, enum `c_oAscCalculateType = {WorkbookOnlyChanged:
   1, ActiveSheet: 2, Workbook: 3, All: 4}`, вызов синхронный (~1,8 с на
   фикстуре 50K) и **добавляет точку в историю правок**. Поэтому JS ставит
   `mutated = true` до вызова, проверка — сдвиг истории
   (`_cdp_check_document_changed`), а после каждого повтора правка
   откатывается (`_restore_history`), как у вставок. Клавиатурного пути нет
   сознательно: F9 живьём не проверен, слепой ввод запрещён. Без CDP шаг
   честно падает с ошибкой «только через api редактора».
3. **Экспорт.** `_save_as_format` через `SpreadsheetOps`, как у тестов
   вкладки: файл пишется в `%TEMP%\temp_export_x2t_*`, формат проверяется по
   содержимому (`_check_export_format`), временные файлы удаляет
   `_cleanup_x2t_temp_pdfs` после каждого файла корпуса. Имена записей —
   как у вкладки (`Сохранение в PDF (конвертация x2t)`), поэтому для них
   работает профиль шума стенда.

Ошибка на файле (окно не появилось, сбой CDP, исключение) не останавливает
корпус: она пишется в запись файла, Р7 закрывается (`_emergency_close_r7`),
дальше следующий файл. Прогон корпуса исключает любой другой прогон,
сценарий, установку и бисект (`RunState`, вид `CORPUS`).

## Манифест `Corpus/corpus.toml`

Необязателен. Нет — все файлы идут по аргументам командной строки. Битый
TOML — предупреждение в журнал и отчёт, прогон по умолчаниям. Неверное поле
записи — предупреждение, поле не учитывается, файл остаётся в прогоне.

```toml
[defaults]                       # поверх аргументов CLI
steps = ["open", "recalc", "export"]
formats = ["pdf"]
open_timeout_sec = 120
open_runs = 5
recalc_runs = 6
export_runs = 6

[files."бюджет-2025.xlsx"]       # путь от Corpus/ через «/» или имя файла
formats = ["pdf", "csv"]
open_timeout_sec = 300
notes = "много сводных таблиц"

[files."черновик.ods"]
skip = true
```

Порядок: аргументы CLI ← `[defaults]` ← `[files."…"]`.

## Отчёты

- `corpus_<ts>.json` — `kind: "corpus"`, `corpus_format: 1`, `measure_schema`,
  `tool_version`, `version`, `build`, `system` (окружение и отпечаток стенда —
  те же помощники, что у полного отчёта), `plan`, `warnings`, `stopped`,
  `hide_names` и `files`: id (первые 12 знаков sha256 содержимого), имя, путь
  от папки, размер, план, заметка, `steps` (записи как у `results` полного
  отчёта: `runs`, `run_statuses`, медиана, MAD, x2t, диск) и `error`.
- `corpus_<ts>.html` — матрица «файл × шаг»: медиана, MAD, годные повторы;
  красная ячейка — ни одного годного повтора, жёлтая — часть отброшена.
- `corpus_compare_<ts>.html` (команда `corpus-compare`) — «файл × версия».

Отчёты корпуса не копируются в общую папку команды: в них имена файлов
клиентов. Нужно поделиться — `--hide-names`.

### `--hide-names`

Имена и пути файлов заменяются id, заметки манифеста и путь к корпусу
убираются, имена вычищаются из текстов ошибок и предупреждений. С флагом
пишется **только** обезличенный JSON и HTML. Файловый журнал
`Reports/logs/` остаётся с именами — он локальный.

## Сравнение «файл × версия»

`corpus-compare база.json версия.json [ещё.json …]`. Первый отчёт — база,
каждый следующий сравнивается с ней. Файлы сопоставляются по id (содержимое),
затем по пути — переобезличенный файл с тем же именем остаётся тем же.
Файлы, которых нет в базе, в сравнение не входят (предупреждение).

Ячейка: медиана версии, сдвиг медианы к базе с 95 %-интервалом и вердикт
`compare_runs` по годным повторам (`valid_runs`). Порог — из профиля шума
стенда для той же операции вкладки (открытие, экспорт; `noise_profile.json`
рядом с базой или `--profile-dir`), иначе 10 %; у пересчёта профиля пока нет.
Поправка Бенджамини-Хохберга — на семью «все ячейки пары база → версия».
Если годных повторов меньше 5 с любой стороны, вердикта нет — «мало
повторов», сдвиг показан. Поэтому по умолчанию открытие идёт 5 раз
(холодные старты, прогрев не отбрасывается), пересчёт и экспорт — по 6
(первый — прогрев, остаётся 5 годных).

Коды выхода `corpus-compare`: 0 — регрессий нет, 1 — есть РЕГРЕССИЯ, 3 —
отчёты не читаются. `corpus`: 0 — все шаги всех файлов дали цифры, 1 — у
части файлов ошибка, 2 — прогон прерван или упал, 3 — не выполнены условия.

## Живые проверки (нужны до первого «боевого» прогона)

Юнит-тесты подменяют Р7. На живом Р7 проверить:

1. `asc_calculate(All)` на рабочей фикстуре через `_cdp_recalculate`:
   `api_ms` около 1,8 с, проверка «позиция в истории: N → N+1», откат
   `_restore_history` возвращает индекс, второй повтор даёт близкое время.
2. Модалка «Автоматический пересчёт может занять время» на тяжёлой книге
   (`showHeavyCalculationWarning`, `isHeavyCalculationWarningEnabled`):
   появляется ли она после `asc_calculate` и закрывает ли её
   `_wait_operation_done` (ответ «Нет», ожидание вычитается).
3. Открытие `.csv`: Р7 может показать окно параметров CSV (кодировка,
   разделитель) до загрузки. Готовность его не закрывает — проверить и, если
   окно есть, доработать открытие или убрать `.csv` из корпуса.
4. Открытие `.xls` и `.ods` (конвертация x2t при открытии) — готовность по
   кнопке «Жирный» срабатывает после конвертации.
5. Экспорт в `xlsx`: пункт «(*.xlsx)» в «Сохранить как» выбирается UIA, файл
   проходит проверку «книга Excel»; экспорт из `.ods` и `.xls`, где Р7 может
   спросить о потере форматирования.
6. Полный цикл на 2–3 файлах: Р7 закрывается после каждого, в `%TEMP%` не
   остаётся `testovarka_corpus_*` и `temp_export_x2t_*`, исходники в `Corpus/` не
   изменились (sha256 тот же), lock-файлов в `Corpus/` нет.
7. Ctrl+C посреди файла: Р7 закрыт, отчёт по пройденным файлам записан,
   код 2.

## Код

| Модуль | Что там |
|---|---|
| `r7/corpus.py` | поиск файлов, манифест, план, запись файла, отчёт, `hide_names` (без Tk и Р7) |

| `templates/html/corpus*.html` | вид страниц |
