# Управление версиями: что проверяется перед установкой и удалением

Инструмент работает от администратора, поэтому всё, что он запускает по
данным извне (реестр, дистрибутив), проверяется до запуска. Код —
`r7/versions.py`, `r7/installers.py`, `r7/elevation.py`, вкладка —
`r7/ui/versions_tab.py`.

## Команда удаления из реестра

Запись `Uninstall` читается из HKLM (64- и 32-битная ветка) и из HKCU —
установка «только для меня». Откуда взята запись, лежит в
`current_version_info["registry_hive"]` (`"HKLM"` / `"HKCU"`). Для
определения версии это хорошо, для запуска команды оттуда — нет: ветку HKCU
переписывает любая программа без прав.

Поэтому `UninstallString` / `QuietUninstallString` проходит
`validate_uninstall_command`. Принимается только Windows Installer:

- исполняемый файл — `msiexec`/`MsiExec.exe` без пути или по пути
  `%SystemRoot%\System32\msiexec.exe` / `SysWOW64\msiexec.exe` (регистр и
  кавычки не важны);
- один ключ `/X{GUID}`; `/I{GUID}` переписывается в `/X` (с `/quiet` это был бы
  тихий ремонт, а не удаление); GUID — строго 8-4-4-4-12 hex-цифр;
- по желанию `/quiet`, `/qn`, `/norestart`; `/quiet /norestart` дописываются,
  если их нет.

Второй допустимый вид — деинсталлятор Inno Setup. Его пишут в реестр
`.exe`-дистрибутивы Р7: живая установка 2026.3.1.3296 (08.10.2026) дала
`UninstallString = "E:\Program Files\R7-Office\Editors\unins000.exe"`, и
без этого вида Batch и бисект не могли удалить версию, поставленную из `.exe`.
`validate_inno_uninstall_command` принимает его, только если:

- запись из HKLM (туда пишет лишь администратор);
- файл называется ровно `unins###.exe`, путь полный, лежит прямо в
  `InstallLocation` той же записи и существует;
- в этой папке есть `DesktopEditors.exe`/`editors.exe`;
- из ключей в записи — только `/SILENT`, `/VERYSILENT`, `/SUPPRESSMSGBOXES`,
  `/NORESTART`.

Запускается всегда с `/VERYSILENT /SUPPRESSMSGBOXES /NORESTART`. Inno
удаляет программу копией деинсталлятора из временной папки, а сам
`unins000.exe` стирает последним, поэтому конец удаления — исчезновение
этого файла (до 5 минут), и только после него — `remove_install_dir`.

Всё остальное — другие программы, лишние аргументы, `&&`, `|`, msiexec не из
System32, символы в GUID, `unins000.exe` из HKCU или не из папки установки —
`ValueError` с причиной.
`uninstall_current_version` ловит её, пишет в строку статуса и в журнал и
возвращает False, ничего не запустив. Popen получает список аргументов,
а не строку.

## Папка установки

После успешного удаления (msiexec или Inno) стирается только `InstallLocation` той же записи
реестра (`remove_install_dir`), а не `C:\Program Files\R7-Office` по
жёсткому пути. Предохранители: папка существует; у пути не меньше трёх частей
(корень диска и `Program Files` целиком не проходят); имя папки содержит
`r7` или `editors`; это не профиль пользователя и не его родитель; до
msiexec внутри был `DesktopEditors.exe`/`editors.exe`
(`install_dir_has_r7_exe`) либо папка после msiexec пуста. Что удалено и что
пропущено — в журнале; `OSError` при удалении ловится и тоже попадает туда.

## Откуда берутся дистрибутивы и чему доверяем

Папки — `Distributives/` рядом с программой плюс `distributives_dirs` из
`r7_settings.json` (`r7/distributives.py`: `all_dirs`, `list_files`). Файлы из
добавленных папок не копируются: установщик весит 430–630 МБ, запоминается папка.
Вкладка «Версии», Batch и `python -m r7 bisect` (без `--dist`) читают все папки,
один и тот же файл — один раз. В таблице вкладки есть колонка «Папка».

По всему компьютеру программа не ищет: обход дисков долгий и непредсказуемый, а
найденное ставится от администратора. Есть только поиск по кнопке «Поискать в
Загрузках» — «Загрузки» (обе локали) и «Рабочий стол», не глубже двух подпапок,
по имени `r7-office*.exe/.msi`, `os.scandir` без символических ссылок, в фоновом
потоке; найденные папки предлагаются к добавлению. Пока идёт прогон, поиск не
запускается (`RunState`, вид `INSTALL`): он читает диск.

**Подпись перед установкой.** `install_version` ставит файл, только если
`distributives.check_installer` вернул «можно»: подпись Authenticode действительна
(`r7.windows.authenticode_signature` — PowerShell `Get-AuthenticodeSignature` без
профиля, списком аргументов, таймаут 60 с) и субъект сертификата содержит издателя
из `TRUSTED_SIGNERS` («AO R7»). Иначе — отказ с причиной в журнале и строке
статуса, Batch и бисект считают это ошибкой установки. Проверка идёт только перед
установкой выбранного файла, а не при показе списка: Windows читает весь файл, и
30 дистрибутивов по 600 МБ при каждом обновлении забили бы файловый кэш, что на
слабом стенде портит следующий замер открытия. Все 33 дистрибутива на стенде
(2025.4–2026.3, `.exe` и `.msi`) подписаны «AO R7» (08.10.2026); живая проверка:
`.exe` и `.msi` проходят за 1,5–2 с, неподписанный файл отклоняется.

## Ключи тихой установки

`/quiet` понимает только msiexec. Все 28 `.exe`-дистрибутивов на стенде —
Inno Setup (07.10.2026, по строке «Inno Setup» в файлах), и с `/quiet` они
открывали мастер. `detect_installer_kind` смотрит расширение (`.msi`) или
первые 8 МБ файла (`Inno Setup` → `inno`, `Nullsoft` → `nsis`);
`silent_args`: msi — `/quiet /norestart`, inno — `/VERYSILENT
/SUPPRESSMSGBOXES /NORESTART`, nsis — `/S`. Неизвестный `.exe` ставится без
тихих ключей: в журнал идёт предупреждение, что откроется мастер, и ожидание
идёт по интерактивному таймауту (30 мин вместо 5).

## Бисект по сборкам

`python -m r7 bisect` (`r7/bisect_runner.py`) ставит сборки сам, тем же
путём, что Batch: `uninstall_current_version` по проверенной команде,
пауза 2 с, `install_version` с тихими ключами по типу установщика,
`detect_current_version`. Уже стоящая сборка второй раз не ставится. В
конце возвращается версия, которая стояла до бисекта, — и после ошибки, и
после Ctrl+C. Её дистрибутив ищется среди сборок по номеру из реестра
(`find_build_for_installed`: точное совпадение или единственная сборка, чей
номер — начало установленного); не нашёлся — бисект не начинается без
`--no-restore`. Подробности — `docs/cli.md`, раздел «Бисект по сборкам».

## Перезапуск от имени администратора

`r7/elevation.py`: `relaunch_as_admin(argv, executable, frozen)` собирает
параметры через `subprocess.list2cmdline` (пути с пробелами доходят
целиком), в сборке PyInstaller передаёт только `argv[1:]` (сам exe и есть
`sys.executable`) и проверяет результат `ShellExecuteW`: больше 32 — копия
запущена, текущий процесс выходит; иначе (отказ в UAC, сбой) программа
продолжает без прав и предупреждает, что установка версий и сброс кэша ОС
недоступны. Корень Tk создаётся до первого `messagebox` и скрыт до сборки
интерфейса.
