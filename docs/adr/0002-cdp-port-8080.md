# 0002. CDP-порт 8080, запасные 8081 и 8082

Статус: принято. Подробности — `docs/readiness.md`, docstring
`r7_webdriver_connector.py`, `r7/readiness.py` (`_pick_cdp_port`).

## Контекст

С флагом `--ascdesktop-support-debug-info` Р7 открывает порт Chrome DevTools
Protocol. Флаг сам выбирает порт: референсная обвязка
(`r7-desktop-selenium`, `conftest.old`) запускает Р7 без
`--remote-debugging-port` и ждёт именно 8080. Что Р7 читает
`--remote-debugging-port`, нигде не подтверждено. Порт 8080 и локатор кнопки
«Жирный» проверены на живом Р7-Офис 24.08.2026.

Порт бывает занят: завис процесс от прошлого прогона, на машине работает
другой сервис.

## Решение

- `DEFAULT_CDP_PORT = 8080` (`r7/env.py`), без динамического выбора
  свободного порта.
- Занят 8080 — пробуются 8081 и 8082 с явным `--remote-debugging-port`. Это
  попытка на удачу: если Р7 флаг не понимает, он его проигнорирует, CDP не
  ответит, и прогон пойдёт по запасному пути.
- Заняты все три — CDP для этого запуска отключается, тест идёт клавишами.
  Это не ошибка, а штатный откат.
- Одна функция выбора порта на всех (`_pick_cdp_port`): вкладка, Batch, свой
  файл и сценарии. Раньше в коде было две копии этой логики.
- Мастер первого запуска проверяет, свободен ли 8080, и предупреждает, что
  иначе операции пойдут клавишами или на 8081/8082.

## Последствия

- Два Р7 с CDP на одной машине одновременно не запустить, и прогоны не идут
  параллельно (`run_state`).
- Запасные порты 8081/8082 на живом Р7 не подтверждены. Если 8080 занят
  посторонним сервисом, CDP, скорее всего, не будет — цифры такого прогона
  несравнимы с CDP-прогонами (ADR 0001).
- Р7 должен закрываться при любом исходе прогона: иначе 8080 остаётся
  занятым, и следующий прогон уходит на клавиши.
