# R7-Testovarka

Инструмент для замеров производительности табличного редактора Р7-Офис: ставит
нужную версию, открывает рабочий файл и повторяет одни и те же операции — выделение,
копирование, вставку, ВПР, экспорт в PDF/ODS/CSV/XLTX. По каждой операции считает
медиану и разброс, сравнивает версии между собой и следит за трендом от прогона к
прогону.

Цифры отражают работу Р7, а не инструмента. Свои паузы инструмент вычитает. Конец
операции определяется по тому, что редактор освободился, а не по последнему нажатию
клавиши. Подготовка теста (лист, выделение, буфер обмена) идёт вне замера. Как это
устроено и чем замер отличается от секундомера — в [`docs/measurement.md`](docs/measurement.md)
и [`docs/precision.md`](docs/precision.md).

## Что нужно

- Windows 10 или 11. Окно Р7 ставится в фиксированный размер, масштаб экрана
  записывается в отчёт (замеры с разным масштабом лучше не сравнивать).
- Python 3.11–3.14, 64-бит.
- Р7-Офис 2026.x. Перед запуском замера Р7 должен быть закрыт.
- Права администратора: без них не сбросить файловый кэш ОС (холодный старт)
  и не поставить или удалить версию.
- Рабочий файл — `TestFiles/файл-для-теста-Р7-офис-50К.xlsx` (50 тысяч строк). Своего
  нет — сгенерируйте его кнопкой «📄 Тестовые файлы» или скриптом:
  `python -c "import r7_Testovarka as m; m.R7Testovarka.__new__(m.R7Testovarka)._generate_fixture('TestFiles/файл-50К.xlsx', rows=50000)"`.

## Установка

```bat
git clone https://github.com/fedintsevqq/r7-testovarka.git
cd r7-testovarka
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Запуск — от имени администратора:

```bat
.venv\Scripts\python.exe r7_Testovarka.py
```

Двойной щелчок по `r7_Testovarka.py` тоже работает: если его открыл системный Python
без нужных пакетов, программа сама перезапустится под `.venv`. Готовый `.exe` собирается
по [`BUILD.md`](BUILD.md).

## Режимы работы

**Вкладка «Версии».** Показывает установленную версию (из реестра) и дистрибутивы из
папки `Distributives/`. «Установить» удаляет текущую версию и ставит выбранную. Пока
идёт любой замер, установка недоступна.

**Вкладка «Производительность».** Слева — 17 тестов, у каждого своё число повторов
(«×N»). По умолчанию: открытие файла — 5 раз, операции правки — 7, экспорты — 3.
«▶ Запустить выбранные тесты» открывает Р7 с рабочим файлом и проходит отмеченные тесты; «Остановить»
прерывает прогон между операциями, отчёт по сделанному всё равно сохраняется. Во время
прогона не трогайте клавиатуру и мышь: инструмент работает с окном Р7. Аварийный выход —
увести мышь в левый верхний угол экрана.

| Группа | Тесты |
|---|---|
| Открытие | повторное открытие файла (каждый раз холодный старт) |
| Правка | Ctrl+A, Ctrl+C, вставка большого массива, новый лист, столбец (клавиши и меню), вставка 1 и 5 ячеек (клавиши и ПКМ), ВПР по 50 тысячам строк, удаление столбца |
| Экспорт через x2t | PDF, ODS, CSV, XLTX |

**Batch.** Проходит те же тесты по нескольким версиям подряд: удаляет текущую, ставит
следующую, меряет, переходит дальше. Повторов — 6 (экспорт в ODS/CSV/XLTX — 3). Есть
пауза, остановка и «останавливаться при первой ошибке». Итог — сводный отчёт по версиям.

**📄 Тестовые файлы.** Генерирует файл нужного размера или берёт ваш и меряет открытие
и ВПР (тест своего файла).

**📊 Сравнить версии.** Выберите от двух до восьми отчётов и базовую версию. Страница
начинается с вывода: сколько регрессий и ускорений и где именно.

**📈 Тренды.** Графики каждой операции по всем сохранённым прогонам, с полосой разброса и
метками смены версии.

Тесты можно запускать только по одному: вкладка, Batch, свой файл и установка не идут
одновременно, потому что все работают с клавиатурой Р7.

## Как читать отчёт

Отчёт прогона — `Reports/Performance_Report_<время>.html`. Рядом лежат Excel и
`performance_full_<время>.json`; JSON нужен для сравнения версий и трендов.

- **Время операции** — медиана повторов. Первый повтор считается прогревом и
  отбрасывается, если после него остаётся хотя бы три. **MAD** — типичное отклонение от
  медианы. Если MAD мал, цифре можно верить.
- **Метки у операции:**
  - `таймаут×N` — Р7 не освободился за отведённое время, такие повторы в медиану не входят;
  - `без подтверждения×N` — редактор не подтвердил, что операция выполнилась, повтор исключён;
  - `зависимые повторы` — правку не удалось откатить между повторами, и каждый следующий
    шёл на изменённом документе;
  - `<порога` — операция быстрее, чем инструмент умеет мерить клавишами;
  - `диск` — время открытия гуляет из-за медленного диска с папкой данных Р7.
- **Условия прогона** — что могло исказить цифры: фоновая нагрузка, работа от батареи,
  мало места на диске. Сюда же попадает, если во время прогона окно Р7 теряло фокус или
  буфер обмена перезаписала другая программа.
- **Сравнение версий.** Вердикт «РЕГРЕССИЯ» или «УСКОРЕНИЕ» ставится, только если
  разница статистически значима (критерий Манна-Уитни) и больше 10 %. Нужно не меньше
  пяти повторов на каждую версию, иначе — «недостаточно прогонов».
- **Версия схемы** (`measure_schema` в JSON). Когда методика замера меняется, номер
  растёт. Отчёты разных схем между собой не сравниваются, и сравнение с трендами об этом
  предупреждают. Текущая схема — 9.

## Ночной прогон

`tests/nightly_local.py --quick` проходит пять ключевых тестов (около 8 минут),
сохраняет отчёт в `Reports/nightly/` и сравнивает его с прошлой ночью. Если хоть одна
операция дала регрессию, скрипт завершится с кодом 2. Запускайте его из Планировщика
заданий в сессии пользователя, не службой. Для GitHub Actions есть workflow
`perf-smoke`, раннер для него описан в [`docs/ci-runner.md`](docs/ci-runner.md).

## Известные ограничения

- **Экспорт рабочего файла в ODS** роняет конвертер x2t: ему не хватает встроенного
  лимита памяти. Это баг Р7 (DE-8304), инструмент только фиксирует падение.
- **Открытие файла зависит от диска**, на котором лежит папка данных Р7
  (`%LOCALAPPDATA%\R7-Office`). На медленном диске каждое четвёртое открытие идёт
  заметно дольше — в отчёте такие повторы помечены меткой «диск».
- **Без пакетов `requests` и `websocket-client`** нет доступа к редактору через CDP.
  Операции тогда идут клавишами, и их цифры несравнимы с обычным прогоном. Тесты через
  контекстное меню без CDP не выполняются. Программа предупреждает об этом перед стартом.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| В журнале `WEBDRIVER_OK=False` | Пакеты стоят не в том Python: `.venv\Scripts\python.exe -c "import requests, websocket"` |
| «Р7 уже запущен» | Закройте Р7-Офис: к уже открытому процессу инструмент не подключается |
| Тест «завис» на одной операции | Предохранитель — 180 с, после него операция получит метку «таймаут», и прогон пойдёт дальше |
| Р7 остался открытым после ошибки | Так не должно быть: инструмент закрывает Р7 при любом исходе. Если всё же случилось — пришлите журнал прогона |

## Для разработчика

Код — пакет [`r7/`](r7/) (замер, процессы, окна, CDP, экспорт, отчёты, интерфейс в
`r7/ui/`). `r7_Testovarka.py` — точка входа, операции тестов — `r7_ops.py`, HTML-отчёты —
`r7_reports.py` с шаблонами из `templates/html/`. Правила и карта кода —
[`CLAUDE.md`](CLAUDE.md), подробности по темам — [`docs/`](docs/).

```bat
.venv\Scripts\python.exe -m pytest -q                                  :: юнит-тесты, без Р7
set R7_LIVE=1 && .venv\Scripts\python.exe -m pytest -m live tests/live :: живой набор, ~1,5 мин
```
